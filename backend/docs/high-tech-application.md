# 企业负责人高新技术企业申报

## 入口与流程

- 企业负责人 → 档案接收 → 已接收企业档案：直接显示每个申报项目名称，不依赖悬浮提示。
- 点击「国家高新技术企业」或包含「高新技术企业」的项目名称，打开对应企业的三步工作页。
- 路由：`/client/enterprise-receipts/:companyId/high-tech`。该路由不单独显示为菜单，仅企业负责人角色可用。
- 页面与接口显式携带企业ID，不改变全局“当前企业”，避免多个企业/标签页之间串用资料。

### 1. 评分

人工填写内部自评分，知识产权30分、成果转化30分、研发组织管理20分、企业成长性20分（销售额增长率10分、净资产增长率10分）。空值代表未评分，0为有效分数。总分实时汇总，上下限由前后端同时校验。不推断法定认定标准，不自动判定是否通过。

### 2. 制作项目详情表

新草稿默认生成9个正式项目（RD01—RD09），按北京时间（Asia/Shanghai）当前年份的前三个完整年度分组，每年3项。例如北京时间2026年：RD01—RD03为2023年度、RD04—RD06为2024年度、RD07—RD09为2025年度。研发周期按年度自动分配，成果序号自动生成，其余字段留空供填写；已保存草稿不补足9项，不自动覆盖年份或非空研发周期。项目表末尾不保留新增输入行。

研发周期仅补齐空白值：按“年份＋RD序号”识别项目，同一项目的关联记录复用已有周期；同年仅一个项目且周期为空时安排1月1日至12月31日，多个空白项目安排错开的8个月周期。仅剩一个空白项目时，结合已有周期补足当年缺口，必要时延长至全年。新草稿每年分别使用1—8月、3—10月、5—12月，合计覆盖全年。

前端在读取草稿、新增或编辑项目、保存前补齐空白周期。读取草稿后补齐周期或整理编号会标记为待保存，并取消材料核对状态；已有材料正文保留。已填写周期即使未覆盖全年、格式无法识别、与所属年份不符或同一RD存在冲突，也只提示核对，不自动覆盖或阻止保存。支持旧版年月格式和常见完整日期范围，覆盖判断精确到日。

14个字段：RD序号、年份、研发活动名称、研发周期、对应知识产权序号、知识产权名称、授权号、授权日期、类型、取得方式、对应PS、成果序号、成果名称、高新技术领域。

每条记录都有「删除」「新增RD」「新增分支」按钮。「新增RD」在当前RD的全部分支之后插入独立项目，默认沿用当前年份；「新增分支」在当前记录下方插入，沿用该RD的前四个字段，其余字段独立填写。空表显示「新增RD」按钮。删除只移除选中记录，保留同RD其他分支；最后一条记录删除后才移除整个RD。

同一RD的前四列（RD序号、年份、研发活动名称、研发周期）合并显示，编辑共享字段同步至所有分支；历史记录存在不一致时，对应列暂不合并，保留原值并提示，用户主动修改后才同步。RD按项目组顺序自动编号为RD01、RD02……，成果序号按全部记录的显示顺序自动编号为成果01、成果02……，新增、删除后重新连续编号。这两个序号不可手动编辑。

支持横向、纵向滚动，项目表不分页以避免跨页合并。最多200条记录（含分支）；草稿允许字段暂空，进入第三步前须填完整。

### 3. 制作高新材料

按已输入事实生成5类可编辑草稿：研发活动、知识产权、科技成果转化、研发组织管理、企业成长性。缺少的信息标为「【待补充】」，不得将含占位提示或空白的材料标记为已核对。生成按钮只填充空白材料，不覆盖人工内容。每份正文最多20,000字；生成结果超限时会提示手动精简，既不截断资料也不覆盖原文。修改评分或项目行会取消材料核对标记，已有正文保留，由用户自行重新核对。

导出为XLSX工作簿，包含自评分、14列项目详情表、5类材料正文共7个工作表。导出前保存当前草稿；项目表按相同RD合并前四列，各分支的其余字段逐行保留，共享字段有历史冲突时对应列不合并。待核对的材料仍可按「草稿」导出；不代表正式申报，不自动生成附件或提交到认定平台。

## 数据库与发布

新增独立表 `biz_high_tech_application`，每个企业保存一份工作草稿。版本号用于乐观并发控制；重新分发或撤销企业权限后，旧负责人无法再读写或导出草稿。

发布后端前，在目标环境执行（幂等、仅新增表）：

```sh
cd backend
npm run db:execute-sql -- sql/high-tech-application.sql
```

随后按项目正常流程构建、重启后端并发布前端。不要仅发布前端而遗漏数据表/接口。生产环境迁移、重启和发布需单独执行；本地联调不代表已上线。已执行迁移的环境应以 `DB_SYNCHRONIZE=false` 启动后端，避免自动同步引入无关表结构变更。

## 接口

以下接口均要求客户端登录且用户能访问该企业，企业须有高新技术企业申报项目。

- `GET /client/companies/:companyId/high-tech-application`：读取草稿；未保存时返回含9个默认项目的未评分草稿、`revision: 0`。
- `PUT /client/companies/:companyId/high-tech-application`：保存 `{ revision, currentStep, scores, projects, materials }`。步骤取0、1、2；版本过期返回409，不覆盖已有修改。
- `GET /client/companies/:companyId/high-tech-application/export`：导出已保存材料；重新检查企业权限与评分、详情完整性。

错误：400数据校验失败；403企业越权或未分配高新项目；409版本冲突；413请求体超过限制。保存接口独立使用10MB JSON请求上限，支持完整中文长材料；其他接口保留原有默认限制。反向代理的该路径请求上限也需至少10MB。
