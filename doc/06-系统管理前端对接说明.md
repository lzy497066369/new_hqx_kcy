# 系统管理前端对接说明

## 1. 范围

本文档只说明后台管理系统 `vue-admin` 的系统管理页面对接规则。当前仓库中的对应目录为 `vue-admin/apps/web-admin`，这里的字段命名以当前前端 API 类型为准：

- 用户管理
- 角色管理
- 菜单管理
- 部门管理

## 2. 页面与接口

### 2.1 用户管理

- 页面：`/system/user`
- 接口：
  - `GET /system/user/list`
  - `POST /system/user`
  - `PUT /system/user/{id}`
  - `DELETE /system/user/{id}`

页面特点：

- 左侧是部门树
- 右侧是用户列表
- 新增和编辑主要依赖用户名称、登录名、部门、角色、状态、备注、首页路径

### 2.2 角色管理

- 页面：`/system/role`
- 接口：
  - `GET /system/role/list`
  - `POST /system/role`
  - `PUT /system/role/{id}`
  - `DELETE /system/role/{id}`

页面特点：

- 列表页支持状态切换
- 编辑页需要挂载菜单权限树
- `permissions` 字段建议继续以菜单 ID 数组传递

### 2.3 菜单管理

- 页面：`/system/menu`
- 接口：
  - `GET /system/menu/list`
  - `POST /system/menu`
  - `PUT /system/menu/{id}`
  - `DELETE /system/menu/{id}`
  - `GET /system/menu/name-exists`
  - `GET /system/menu/path-exists`

页面特点：

- 树表结构
- 新增/编辑时要校验名称和路径唯一性
- `type` 分为 `catalog`、`menu`、`button`

### 2.4 部门管理

- 页面：`/system/dept`
- 接口：
  - `GET /system/dept/list`
  - `POST /system/dept`
  - `PUT /system/dept/{id}`
  - `DELETE /system/dept/{id}`

页面特点：

- 树表结构
- 新增和编辑支持父部门选择

## 3. 前端字段约定

### 3.1 用户

```ts
{
  [key: string]: any;
  id: string;
  username?: string;
  deptId?: string | null;
  deptName?: string | null;
  homePath?: string | null;
  name: string;
  password?: string;
  permissions?: string[];
  roleIds?: string[];
  roleNames?: string[];
  status: 0 | 1;
  remark?: string | null;
}
```

### 3.2 角色

```ts
{
  [key: string]: any;
  id: string;
  code?: string;
  name: string;
  permissions?: string[];
  status: 0 | 1;
  remark?: string | null;
}
```

### 3.3 菜单

```ts
{
  [key: string]: any;
  id: string;
  parentId?: string | null;
  name: string;
  path: string;
  component?: string | null;
  redirect?: string | null;
  type: 'catalog' | 'menu' | 'button';
  status: 0 | 1;
  authCode?: string | null;
  orderNum?: number;
  meta: {
    title: string;
    icon?: string | null;
  };
  children?: Array<...>;
  createTime?: string;
  updateTime?: string;
}
```

### 3.4 部门

```ts
{
  [key: string]: any;
  id: string;
  parentId?: string | null;
  name: string;
  status: 0 | 1;
  remark?: string | null;
  sortNum?: number;
  children?: Array<...>;
  createTime?: string;
  updateTime?: string;
}
```

## 4. 实现建议

- 列表页优先走 `items + total` 的返回结构，适配 Vxe Grid。
- 菜单和部门页优先走树形数组，页面更直接。
- 角色权限建议与菜单树联动，不要单独维护一套重复权限结构。
- 后端在创建和编辑时，应尽量自动补齐默认值，减少前端表单复杂度。
- 用户管理表单需要兼容 `name`、`username`、`deptId`、`roleIds`、`status`、`remark`、`homePath`。
- 菜单管理表单需要兼容 `name`、`path`、`component`、`redirect`、`type`、`authCode`、`orderNum`、`status`、`meta`。
- 部门管理表单需要兼容 `name`、`parentId`、`sortNum`、`status`、`remark`。

## 5. 当前结论

后台管理系统的系统页已经具备基本框架，后端只要保持这几个接口和字段稳定，页面就可以直接联调。后续新增系统管理页面，也建议继续沿用同一套字段名和返回风格。
