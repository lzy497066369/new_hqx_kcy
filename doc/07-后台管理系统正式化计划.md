# 后台管理系统正式化计划

## 1. 阶段目标

本阶段目标是把后台管理系统从“页面和接口骨架可用”推进到“可稳定联调、可验收、可继续承载业务模块”的状态。

本阶段只聚焦后台管理系统：

- 前端目录：`vue-admin/apps/web-admin`
- 后端目录：`backend`
- 数据库目标：兼容 `MySQL 5.6.50-log`

客户端操作系统 `vue-admin/apps/web-client` 暂不作为本阶段主线，只保留后续对接边界。

当前进度：

- P0（接口收口、权限链路、操作日志、数据库脚本、应用身份收口、四页联调）：已完成并验收。
- P1（Mock 清理、最小验证命令、文档同步）：Mock 清理进行中，最小验证命令已整理，文档同步已完成。
- 当前优先继续推进线程 7 的 Mock 清理收尾，然后按最小验证命令做一次冒烟确认。

## 2. 不做范围

为避免范围扩散，本阶段暂不优先做以下内容：

- 不新开企业资料、申报、政策、AI 等业务模块。
- 不重构 Vben 框架底层结构。
- 不引入新的权限体系或新的接口返回协议。
- 不扩大客户端页面开发范围。

## 3. P0 任务

### 3.1 后端系统管理接口收口

目标：让系统管理四个核心模块的增删改查稳定可用。

范围：

- 用户管理：`/system/user/list`、`POST /system/user`、`PUT /system/user/{id}`、`DELETE /system/user/{id}`
- 角色管理：`/system/role/list`、`POST /system/role`、`PUT /system/role/{id}`、`DELETE /system/role/{id}`
- 菜单管理：`/system/menu/list`、`POST /system/menu`、`PUT /system/menu/{id}`、`DELETE /system/menu/{id}`
- 部门管理：`/system/dept/list`、`POST /system/dept`、`PUT /system/dept/{id}`、`DELETE /system/dept/{id}`

验收标准：

- 四个模块都能完成列表、新增、编辑、删除。
- 用户和部门能关联。
- 角色和菜单权限能关联。
- 菜单和部门能按树形结构返回。
- 接口返回格式统一为 `code`、`data`、`message`。

### 3.2 权限链路闭环

目标：登录后能拿到用户身份、菜单和权限码，后台按权限显示。

范围：

- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /user/info`
- `GET /auth/codes`
- `GET /menu/all`

验收标准：

- 登录后能进入后台。
- 当前用户信息稳定返回。
- 菜单树按用户角色返回。
- 权限码与角色菜单权限来自同一套数据。
- 前端按钮和菜单显示不依赖硬编码。

### 3.3 操作日志落地

目标：后台关键操作可追踪。

范围：

- 登录成功和失败日志。
- 用户、角色、菜单、部门的新增、编辑、删除日志。
- 状态切换日志。
- 操作日志列表查询。

验收标准：

- 关键操作能写入数据库。
- 日志字段包含操作人、操作模块、操作类型、请求信息、结果、时间。
- 操作日志页面能查询记录。
- 日志表结构兼容 MySQL 5.6。

### 3.4 数据库脚本定版

目标：形成一套可靠的建库和升级脚本。

范围：

- `backend/sql/schema.sql`
- `backend/sql/schema.mysql56.sql`
- 操作日志相关补丁脚本。
- 迁移和修复脚本。

验收标准：

- 新环境可以使用脚本完成初始化。
- 旧环境可以按补丁脚本升级。
- 脚本不使用 MySQL 8 专属能力。
- 字段默认值、索引、外键或关联表约定清晰。

### 3.5 `web-admin` 应用身份收口

目标：让 `vue-admin/apps/web-admin` 成为明确的后台管理系统入口。

范围：

- 修正应用名称和 package 信息。
- 检查环境变量。
- 检查启动和构建脚本。
- 清理旧应用名和迁移残留命名。

验收标准：

- 启动、构建、类型检查命令都指向 `web-admin`。
- 文档和代码中的主应用名称一致。
- 后续开发不再依赖旧应用名或已移除的迁移目录。

### 3.6 系统管理页面正式接口联调

目标：后台四个系统管理页面全部走正式接口。

范围：

- `/system/user`
- `/system/role`
- `/system/menu`
- `/system/dept`

验收标准：

- 列表能加载真实数据。
- 筛选、分页、树形展示可用。
- 新增、编辑、删除、状态切换可用。
- 表单字段与后端字段一致。
- 页面不再依赖对应 mock 数据。

## 4. P1 任务

### 4.1 Mock 清理

目标：已联调完成的模块逐步退出 mock。

状态：进行中，线程 7 正在收尾。

验收标准：

- 系统管理主流程不依赖 `backend-mock`。
- 只保留未开发模块的 mock。
- 前端环境切换规则清晰。

### 4.2 最小验证命令

目标：每次交付前能用最小成本确认没有破坏主链路。

状态：已整理，可直接执行。

建议命令：

- 后端：`npm run build`
- 后端：`npm run lint`
- 后台前端：`pnpm -F @vben/web-admin run typecheck`
- 后台前端：`pnpm -F @vben/web-admin run build`

验收标准：

- 后端能构建。
- 前端能类型检查和构建。
- 登录、菜单、系统管理四页完成一次冒烟验证。

### 4.3 文档同步

目标：让代码、接口、数据库和联调说明保持一致。

状态：已完成。

范围：

- 更新接口字段。
- 更新数据库脚本执行方式。
- 更新联调顺序。
- 更新环境变量和代理说明。

验收标准：

- 新人按文档可以知道先启动什么、调什么接口、如何验收。
- 文档中不再混用旧应用名和旧路径。

## 5. P2 任务

### 5.1 第一个后台业务模块准备

目标：在系统管理正式化后，再选择第一个业务模块。

选择原则：

- 优先选择复用用户、角色、菜单、部门能力的模块。
- 优先选择字段边界清楚、流程短、联调成本低的模块。
- 不优先选择 AI、复杂申报流、跨端强依赖模块。

候选方向：

- 企业管理基础模块。
- 内容管理基础模块。
- 申报配置基础模块。

## 6. 推荐执行顺序

1. 后端系统管理接口收口。
2. 权限链路闭环。
3. 操作日志落地。
4. 数据库脚本定版。
5. `web-admin` 应用身份收口。
6. 系统管理四页联调。
7. Mock 清理。
8. 最小验证和文档同步。

## 7. 阶段完成标准

满足以下条件后，才能认为“后台管理系统正式化”完成：

- 管理员可以登录后台。
- 菜单和按钮权限按角色生效。
- 用户、角色、菜单、部门可以完整增删改查。
- 操作日志可以记录关键后台动作。
- 数据库脚本可以支撑新环境初始化和旧环境升级。
- `web-admin` 是明确、稳定的后台管理系统入口。
- 系统管理主流程不依赖 mock。
- 后端和前端能通过最小构建或类型检查。

## 8. 下一阶段入口

后台管理系统正式化完成后，再进入客户端操作系统和业务模块开发。

建议下一阶段优先级：

1. 客户端登录、用户信息、企业切换。
2. 企业资料维护。
3. 申报项目查看和提交。
4. 补件和结果查看。
5. 内容、消息和 AI 辅助入口。
