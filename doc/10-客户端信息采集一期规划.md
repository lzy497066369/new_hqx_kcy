# 客户端信息采集一期规划

## 1. 阶段目标

客户端一期先分两步推进：P0 先把客户端基础链路跑通，确保企业用户能登录客户端、识别可访问企业、切换当前企业，并进入客户端首页、个人情况页和公司资料页；P1 再进入企业资料维护和材料模板上传。后台主要维护企业、账号绑定关系、表格模板、字段规则和版本。

一期闭环：

P0 基础链路：

1. 企业用户登录客户端
2. 系统根据账号、邮箱或绑定关系识别可访问企业
3. 用户选择或切换当前企业
4. 进入客户端首页
5. 查看个人情况页和公司资料页入口
6. 公司切换后刷新当前企业上下文

P1 企业资料与材料上传：

1. 查看公司资料完整度和待补全项
2. 在线维护公司基础信息和联系人信息
3. 下载材料模板并线下填写
4. 上传已填写模板和附件材料
5. 提交资料校验
6. 系统按规则自动通过或退回
7. 企业按校验结果继续补全

## 2. 一期范围

### 2.1 必做模块

| 模块 | 说明 |
| --- | --- |
| P0 客户端首页 | 面向企业用户展示当前企业、基础状态和快捷入口 |
| P0 账号企业识别 | 根据登录账号、邮箱、手机号或绑定关系识别可访问企业 |
| P0 企业切换 | 支持一个账号绑定多家公司，并切换当前操作企业 |
| P0 个人情况 | 展示和维护当前登录人的姓名、手机号、邮箱、职位、经办身份等信息 |
| P0 公司资料页 | 先做公司档案入口和基础展示，不在 P0 做完整上传流程 |
| P1 企业基础信息 | 维护企业名称、统一社会信用代码、注册地址、经营范围等核心字段 |
| P1 联系人信息 | 维护企业负责人、经办人、联系电话、邮箱等信息 |
| P1 材料模板中心 | 提供标准模板下载、上传回传、版本管理和填写说明 |
| P1 材料上传记录 | 展示已上传材料、解析状态、自动校验状态和退回原因 |
| P2 提交预览 | 提交前汇总企业信息和材料清单，减少漏填漏传 |
| P2 退回修改记录 | 展示系统校验退回意见和企业补正记录 |

### 2.2 暂不纳入一期

| 模块 | 暂缓原因 |
| --- | --- |
| 申报项目提交 | 先把企业资料底座稳定后再接申报 |
| 政策问答 | 依赖内容库和问答规则，优先级低于资料采集 |
| AI 辅助填报 | 依赖结构化资料和模板沉淀，一期先预留入口 |
| 内容中心 | 可后续作为企业运营内容入口扩展 |

## 4. 账号与企业关系

客户端必须先解决“当前用户代表哪家公司操作”的问题。企业资料、材料上传和后续申报都应绑定到当前企业，而不是只绑定到个人账号。

### 4.1 识别方式

| 方式 | 说明 |
| --- | --- |
| 账号绑定 | 后台或注册流程维护账号与企业的绑定关系 |
| 邮箱识别 | 登录邮箱可作为企业成员识别线索，但不应作为唯一可信依据 |
| 手机号识别 | 手机号可用于找回、邀请和经办人确认 |
| 统一社会信用代码 | 企业绑定和新增企业时用于确认企业主体 |

### 4.2 企业切换规则

| 规则 | 说明 |
| --- | --- |
| 一个账号可绑定多家公司 | 适配代理经办人、集团人员、多企业负责人 |
| 必须有当前企业上下文 | 进入公司资料、材料上传前必须确定当前企业 |
| 支持默认公司 | 用户可设置登录后默认进入的公司 |
| 切换公司后刷新业务数据 | 公司资料、材料记录、完整度、待办都按当前企业重新读取 |
| 无绑定企业时进入绑定流程 | 引导用户填写企业名称、统一社会信用代码和联系方式 |

### 4.3 客户端数据维护边界

| 数据 | 客户端可维护 | 后台维护 |
| --- | --- | --- |
| 个人情况 | 姓名、手机号、邮箱、职位、经办身份 | 账号状态、角色、绑定企业 |
| 公司基础资料 | 企业基本信息、联系人、经营信息 | 企业状态、企业归属、必要的锁定字段 |
| 材料数据 | 下载模板、上传模板、查看校验结果 | 模板、字段、填写说明、校验规则 |
| 企业绑定关系 | 发起绑定或切换当前企业 | 审核或维护账号与企业关系 |

## 5. 客户端展示方式

客户端不能照搬后台管理系统的表格 CRUD 风格。后台面向管理员，强调列表、筛选、批量维护；客户端面向企业用户，应该强调“当前该做什么、资料还缺什么、下一步去哪儿”。

### 5.0 客户端与后台差异

| 对比项 | 后台管理系统 | 客户端操作系统 |
| --- | --- | --- |
| 使用对象 | 平台管理员、业务管理员 | 企业负责人、企业经办人 |
| 核心目标 | 维护数据、配置规则、管理账号和模板 | 查看当前企业、补全资料、上传材料、处理待办 |
| 首页形态 | 管理菜单 + 数据列表入口 | 当前企业工作台 + 待办 + 快捷操作 |
| 页面组织 | 按管理对象分模块，如用户、企业、模板、规则 | 按企业用户任务组织，如个人情况、公司资料、材料上传 |
| 主要交互 | 表格查询、新增、编辑、删除、批量操作 | 进度提示、步骤引导、下载模板、上传资料、查看结果 |
| 数据视角 | 看全量企业和全量账号 | 只看当前账号可访问的企业 |
| 权限逻辑 | 管理员角色决定能管理哪些模块 | 当前账号绑定关系决定能操作哪家公司 |
| 文案风格 | 管理、配置、维护、启用、禁用 | 我的公司、我的资料、去补全、下载模板、上传材料 |
| 页面密度 | 信息密度高，适合管理人员反复筛选 | 信息密度适中，突出下一步动作 |

### 5.1 P0 展示差异落点

P0 先跑通客户端时，至少要让用户一眼感到这不是后台换皮。

| 页面 | 客户端做法 | 避免做法 |
| --- | --- | --- |
| 客户端首页 | 展示当前公司、账号身份、待补全提醒和快捷入口 | 不做后台 dashboard 图表堆叠 |
| 公司切换页 | 用公司卡片或简洁列表展示“我可操作的公司” | 不做企业管理列表，不出现批量删除、状态筛选等后台动作 |
| 个人情况页 | 展示我的联系方式、经办身份、绑定公司 | 不做用户管理详情页，不展示后台角色配置 |
| 公司资料页 | 用公司档案视角展示基础信息入口、材料入口和完成状态 | 不做企业 CRUD 表单全集 |

### 5.2 P1 展示差异落点

P1 做企业资料上传时，也要继续保持企业用户办事视角。

| 页面 | 客户端做法 | 后台对应能力 |
| --- | --- | --- |
| 公司基础信息 | 分块填写公司信息，突出保存和待补全项 | 后台维护企业主数据和必要锁定字段 |
| 联系人信息 | 维护负责人、经办人、默认联系人 | 后台查看或维护企业绑定关系 |
| 材料模板中心 | 按材料类型展示模板卡片，提供下载、上传、校验结果 | 后台维护模板文件、字段和规则 |
| 校验结果 | 直接告诉用户哪一行、哪个字段错了，以及怎么改 | 后台维护校验规则，不做默认人工审核 |

### 5.3 展示原则

| 原则 | 说明 |
| --- | --- |
| 以当前企业为中心 | 顶部或显著位置展示当前企业，支持快速切换 |
| 以任务进度为主 | 首页优先展示资料完整度、待补全项、最近上传状态 |
| 减少后台式列表 | 企业用户常用动作做成步骤、卡片、分区入口，而不是大表格堆叠 |
| 明确下一步动作 | 每个模块给出下载模板、上传材料、补全信息、查看错误等主操作 |
| 保留材料状态可追踪 | 上传版本、校验结果、错误原因要清楚可查 |

### 5.4 页面风格建议

| 页面 | 展示方式 |
| --- | --- |
| 客户端首页 | 工作台式布局，突出当前企业、完成度、待办和快捷入口 |
| 公司资料页 | 档案式布局，按基础信息、联系人、材料、校验结果分区 |
| 个人情况页 | 简洁表单 + 账号绑定信息，不做后台用户管理页 |
| 材料模板中心 | 模板卡片或分组列表，突出下载、上传、最近校验结果 |
| 公司切换页 | 公司列表 + 当前公司标识 + 默认公司设置 |

## 6. P1 材料模板机制

材料部分放到 P1，建议设计成“模板驱动”的快捷采集方式。企业用户不需要在网页里逐项录入复杂表格，而是下载标准模板，线下整理后上传回系统。

### 6.1 适合模板化的材料

| 材料类型 | 模板形式 | 说明 |
| --- | --- | --- |
| 员工信息 | Excel | 适合批量维护姓名、岗位、学历、社保等字段 |
| 财务信息 | Excel | 适合按年度填写营收、税收、研发投入等数据 |
| 知识产权 | Excel | 适合批量维护专利、软著、商标等记录 |
| 合同信息 | Excel | 适合批量维护合同名称、金额、甲乙方、签订日期 |
| 证照资质 | PDF/图片附件 + 清单模板 | 证照文件上传，清单用于结构化登记 |
| 图片资料 | 图片附件 | 厂房、设备、场景照片等非结构化材料 |

### 6.2 用户流程

1. 用户进入材料模板中心
2. 选择材料类型
3. 下载最新模板
4. 线下填写模板
5. 上传已填写文件
6. 系统记录上传版本
7. 后端做基础校验
8. 校验通过后自动通过
9. 校验失败时返回错误行和错误原因
10. 企业按错误提示修改后重新上传

### 6.3 模板管理规则

| 规则 | 说明 |
| --- | --- |
| 模板必须有版本号 | 便于后续字段变更和历史文件识别 |
| 上传文件必须关联模板版本 | 后端按模板版本解析和校验 |
| 不覆盖历史上传 | 每次上传生成一条材料版本记录 |
| 支持重新上传 | 企业可在退回后上传新版本 |
| 支持填写说明 | 模板下载页展示字段说明、示例和注意事项 |
| 支持错误反馈 | 解析失败时返回行号、字段名、错误原因 |
| 默认自动校验 | 系统按模板规则、必填项、格式、取值范围和附件要求自动判断 |
| 后台维护表格 | 后台维护模板文件、字段清单、填写说明、校验规则和版本状态 |

### 6.4 自动校验规则

自动校验分三层：

| 层级 | 规则 | 结果 |
| --- | --- | --- |
| 文件校验 | 文件类型、大小、模板版本、是否可解析 | 不通过则直接退回 |
| 字段校验 | 必填项、格式、枚举值、数字范围、日期范围 | 不通过则返回错误行和错误原因 |
| 完整度校验 | 材料类型是否齐全、附件是否匹配清单、企业基础信息是否完整 | 不通过则生成待补全项 |

自动校验结果：

| 结果 | 说明 |
| --- | --- |
| `valid` | 自动校验通过，可进入资料汇总 |
| `invalid` | 自动校验不通过，企业按错误原因修改后重新上传 |

## 7. 状态流转

企业资料状态：

| 状态 | 说明 |
| --- | --- |
| `draft` | 草稿，企业正在填写或上传材料 |
| `checking` | 已提交，系统正在自动校验 |
| `valid` | 自动校验通过，资料可进入后续申报使用 |
| `invalid` | 自动校验不通过，企业需要修改后重新提交 |

材料状态：

| 状态 | 说明 |
| --- | --- |
| `not_uploaded` | 未上传 |
| `uploaded` | 已上传，等待系统校验 |
| `invalid` | 校验失败，需要重新上传 |
| `valid` | 自动校验通过 |

## 11. 验收标准

P0 完成后应满足：

1. 企业用户登录后能识别可访问企业
2. 一个账号绑定多家公司时能切换当前企业
3. 无绑定企业时能进入企业绑定流程
4. 企业用户能维护个人情况
5. 企业用户能进入客户端首页
6. 企业用户能进入公司资料页，并看到当前公司基础信息入口
7. 切换公司后首页、个人页、公司资料页使用同一个当前企业上下文

P1 完成后应满足：

1. 企业用户能在公司资料页看到资料完整度和待补全项
2. 企业用户能保存公司基础信息和联系人信息
3. 企业用户能下载最新材料模板
4. 企业用户能上传填写后的模板文件
5. 系统能展示上传状态和校验错误
6. 企业用户能提交资料并触发自动校验
7. 系统能按模板规则自动通过或返回错误
8. 后台能维护模板文件、字段和自动校验规则
