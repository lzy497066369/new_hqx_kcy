# 客户端开发顺序

## 1. 排序结论

客户端不要先做材料上传、申报、政策问答或内容中心。当前最稳的顺序是：

1. P0 先跑通账号与企业上下文。
2. P0 再跑通客户端首页、公司切换、个人情况、公司资料页。
3. P1 再做企业资料维护、联系人维护、材料模板下载和上传。
4. P2 再做提交预览、退回修改记录和补正闭环。
5. P3 以后再接申报项目、政策中心、内容中心和 AI 辅助。

核心原因：客户端所有业务都必须先知道“当前账号代表哪家公司操作”。没有当前企业上下文，企业资料、材料上传、申报提交都会变成散点功能。

## 2. 当前基础

根据 `doc/00-项目总览.md`、`doc/08-功能总表.md`、`doc/10-客户端信息采集一期规划.md` 和当前代码状态，客户端现状可以按下面理解：

- `vue-admin/apps/web-client` 已经存在客户端应用骨架。
- 已有登录、请求封装、基础路由能力。
- 已有 `src/router/routes/modules/client.ts`，目前只挂了 `ClientEnterpriseUser`。
- 已有 `src/views/client/enterprise-user/index.vue`，更适合作为账号资料或原型参考，不建议继续承载企业主体资料。
- 已有 `src/api/enterprise/client.ts`，当前接口是 `GET /enterprise/client/current`，可作为临时参考，但后续建议收口到 `src/api/client/*`。

## 3. P0 基础链路

目标：企业用户登录后，系统能识别可访问企业，能切换当前企业，并进入客户端首页、个人情况页和公司资料页。

### P0-0 接口和数据模型定版

先定字段和最小模型，避免前端页面先写死假数据。

交付物：

- `enterprise_account`：账号与企业绑定关系。
- `client_user_profile`：客户端个人情况。
- `enterprise_profile`：企业基础资料主表。
- 当前企业上下文规则：默认企业、切换企业、无绑定企业处理。
- 统一响应格式继续使用 `code/data/message`。

验收：

- 能明确一个账号绑定一家或多家企业时的数据结构。
- 能明确无绑定企业时走绑定流程，而不是进入空白页。

### P0-1 后端客户端基础接口

先做读取类和上下文类接口，保证前端可以真实联调。

优先接口：

| 顺序 | 接口 | 方法 | 用途 |
| --- | --- | --- | --- |
| 1 | `/client/me` | `GET` | 获取当前登录人信息 |
| 2 | `/client/companies` | `GET` | 获取当前账号可访问企业 |
| 3 | `/client/companies/current` | `GET` | 获取当前操作企业 |
| 4 | `/client/companies/current` | `PUT` | 切换当前操作企业 |
| 5 | `/client/enterprise/profile` | `GET` | 获取当前企业资料 |
| 6 | `/client/me` | `PUT` | 保存个人情况 |
| 7 | `/client/companies/bind` | `POST` | 发起企业绑定 |

后台配套接口：

- 企业主数据查看和维护。
- 企业账号绑定关系查看、新增、修改。

验收：

- 登录后能拿到当前用户、可访问企业列表、当前企业。
- 切换企业后再次读取首页和公司资料，数据跟随当前企业变化。

### P0-2 前端 API 与企业上下文

再做前端 API 层和当前企业上下文，不急着堆页面。

建议新增：

```text
vue-admin/apps/web-client/src/api/client/
  account.ts
  company.ts
  enterprise.ts
```

建议实现：

- `account.ts`：`/client/me`、`/client/companies/bind`。
- `company.ts`：`/client/companies`、`/client/companies/current`。
- `enterprise.ts`：`/client/enterprise/profile`。
- 当前企业状态：可以先用页面级状态或轻量 store，后续再沉淀成通用 composable。

验收：

- 页面不直接散写 URL。
- 当前企业 ID、名称、默认企业状态能被首页、公司切换、公司资料页共用。

### P0-3 前端 P0 页面

在基础接口可用后新增页面和路由。

建议顺序：

| 顺序 | 页面 | 文件建议 | 路由 |
| --- | --- | --- | --- |
| 1 | 客户端首页 | `src/views/client/home/index.vue` | `/client/home` |
| 2 | 公司切换 | `src/views/client/company-switch/index.vue` | `/client/company-switch` |
| 3 | 个人情况 | `src/views/client/profile/index.vue` | `/client/profile` |
| 4 | 公司资料页 | `src/views/client/enterprise-profile/company.vue` | `/client/company` |

页面重点：

- 首页：当前企业、资料状态、待补全提示、快捷入口。
- 公司切换：我可操作的公司、当前公司、默认公司设置。
- 个人情况：姓名、手机号、邮箱、职位、经办身份、绑定公司。
- 公司资料页：公司档案总览、基础信息入口、材料入口占位、完成状态。

验收：

- 用户能完整跑通 `登录 -> 当前企业 -> 首页 -> 公司切换 -> 个人情况 -> 公司资料页`。
- 公司切换后，首页、个人情况页、公司资料页使用同一个当前企业上下文。
- 公司资料页只做档案入口和基础展示，不在 P0 做完整上传流程。

## 4. P1 资料维护与材料上传

目标：企业用户能维护公司资料和联系人，能下载模板、上传材料，并看到校验状态。

### P1-0 材料模板规则先定版

先定模板清单、字段、版本和校验规则，再做上传页面。

交付物：

- 材料类型清单：员工信息、财务信息、知识产权、合同信息、证照资质、图片资料。
- 模板版本规则。
- 文件类型、大小、必填项、格式、枚举值、范围、附件要求。
- 错误反馈结构：行号、字段名、错误原因。

### P1-1 后台模板和规则维护

后台先提供模板配置能力，否则客户端上传页没有真实模板来源。

接口：

- `/admin/material-templates`
- `/admin/material-templates/:id`
- `/admin/material-templates/:id/rules`
- `/admin/materials/:id`

验收：

- 后台能维护模板文件、字段说明、版本状态和自动校验规则。

### P1-2 客户端企业资料维护

页面：

- `src/views/client/enterprise-profile/company-basic.vue`
- `src/views/client/enterprise-profile/company-contacts.vue`

接口：

- `PUT /client/enterprise/profile`
- `GET /client/enterprise/contacts`
- `POST /client/enterprise/contacts`
- `PUT /client/enterprise/contacts/:id`

验收：

- 企业用户能保存公司基础信息。
- 企业用户能维护负责人、经办人、默认联系人。
- 公司资料页能展示资料完整度和待补全项。

### P1-3 客户端材料模板与上传

页面：

- `src/views/client/enterprise-profile/company-materials.vue`
- `src/views/client/enterprise-profile/components/MaterialTemplateList.vue`
- `src/views/client/enterprise-profile/components/MaterialUploadPanel.vue`
- `src/views/client/enterprise-profile/components/ProfileCompleteness.vue`

API 文件：

```text
vue-admin/apps/web-client/src/api/client/material.ts
```

接口：

- `GET /client/material-templates`
- `GET /client/material-templates/:id/download`
- `POST /client/materials/upload`
- `GET /client/materials`
- `GET /client/materials/:id/errors`
- `POST /client/enterprise/profile/submit`

验收：

- 用户能下载最新模板。
- 用户能上传已填写模板或附件。
- 系统能记录上传版本。
- 校验失败时能展示错误行、错误字段和错误原因。
- 校验通过后资料状态进入 `valid` 或可提交状态。

## 5. P2 提交预览与退回补正

目标：把资料维护和材料上传变成可检查、可追踪、可补正的闭环。

页面：

| 页面 | 文件建议 | 路由 |
| --- | --- | --- |
| 提交预览 | `src/views/client/enterprise-profile/company-preview.vue` | `/client/company/preview` |
| 退回修改记录 | `src/views/client/enterprise-profile/company-revisions.vue` | `/client/company/revisions` |

接口：

- `GET /client/enterprise/profile/revisions`
- 复用 `POST /client/enterprise/profile/submit`

验收：

- 提交前能汇总企业基础信息、联系人和材料清单。
- 能提示缺失项，避免漏填漏传。
- 能查看退回原因、补正记录和重新提交入口。

## 6. P3 后续业务

这些模块不要抢在 P0/P1 前面做：

- 申报项目查看和提交。
- 补件和结果查看。
- 政策中心。
- 内容中心。
- 政策问答。
- AI 辅助填报。

进入条件：

- P0 当前企业上下文稳定。
- P1 企业资料和材料模板上传稳定。
- 后台已有对应配置、审核或内容管理能力。

## 7. 最小开发节奏建议

建议按小闭环推进，每个闭环都能验收：

1. 后端完成当前企业上下文读取和切换。
2. 前端完成 `src/api/client/*` 基础 API。
3. 前端完成首页、公司切换、个人情况、公司资料页路由和页面。
4. 完成 P0 冒烟验证。
5. 后台完成企业主数据和账号绑定维护。
6. 后台完成模板、字段、规则维护。
7. 前端完成公司基础信息和联系人维护。
8. 前端完成材料模板下载、上传和错误反馈。
9. 完成 P1 冒烟验证。
10. 最后做提交预览和退回修改记录。

## 8. 暂不建议做的事

- 不建议把 `enterprise-user` 页面继续扩成公司资料大页，它更像账号中心。
- 不建议先做材料上传 UI，因为模板和校验规则没定时返工概率高。
- 不建议先做申报项目，因为申报依赖企业资料底座。
- 不建议把客户端做成后台 CRUD 换皮，客户端应该围绕当前企业、待补全项和下一步动作组织页面。
