# 申报材料要求与准备度开发方案

## 1. 目标

申报项目模块负责把企业资料用于具体项目申报场景，回答下面 4 个问题：

1. 当前项目需要哪些材料。
2. 当前企业已有资料满足哪些要求。
3. 当前企业还缺哪些材料、字段或附件。
4. 当前申报准备度、风险等级和补齐建议是什么。

企业资料模块只作为资料底座，负责资料录入、专表存储、通用统计和健康分。申报项目模块负责项目材料规则、企业资料匹配、准备度评分和申报流程提示。

## 2. 边界原则

- 企业资料模块不写项目申报规则。
- 申报项目模块不重复存企业资料明细，只引用企业资料专表和统计结果。
- 项目材料要求归属申报项目侧。
- 申报准备度评分独立于企业资料健康分。
- 正式申报提交前再做材料快照，避免企业资料后续变更影响已提交申报。

## 3. 整体链路

```text
后台配置项目材料要求
        ↓
客户端进入可申报项目详情
        ↓
系统读取当前企业资料专表和统计结果
        ↓
逐条匹配项目材料要求
        ↓
生成材料检查结果和准备度分数
        ↓
创建申报草稿时提示缺失材料
        ↓
正式提交前生成申报材料快照
```

## 4. 数据库规划

### 4.1 第一期表

第一期先做项目材料要求和检查结果闭环。

| 表名 | 用途 |
| --- | --- |
| `biz_project_material_requirement` | 项目材料要求主表 |
| `biz_project_material_requirement_item` | 项目材料要求明细 |
| `biz_declaration_material_check` | 某企业/项目/申报的材料检查主表 |
| `biz_declaration_material_check_item` | 材料检查明细 |

第二期做正式申报材料快照。

| 表名 | 用途 |
| --- | --- |
| `biz_declaration_material_snapshot` | 申报材料快照，保存当时引用的企业资料和文件 |

| 模块 | `module_key` | 常用 `tab_key` |

## 7. 匹配规则

每条项目材料要求从对应企业资料模块中匹配资料，检查以下条件：

| 检查项 | 说明 |
| --- | --- |
| 数量 | `matched_count >= required_count` |
| 年份 | 如果配置 `required_years`，资料年份必须覆盖要求年份 |
| 必填字段 | `required_fields` 中的字段必须有值 |
| 附件 | `attachment_required = 1` 时必须找到附件字段 |
| 必交 | `is_required = 1` 的要求缺失会影响整体状态 |

附件字段建议沿用企业资料健康分里的口径：

| 子模块 | 附件字段 |
| --- | --- |
| `finance/taxAudit` | `file_path` |
| `employee/employees` | `yg_files` |
| `property/intellectualProperty` | `soft_work_file` |
| `property/researchProject` | `lxbg_file` |
| `contract/contracts` | `ht_path` |
| `document/documents` | `file_path` |
| `certificate/certificates` | `zs_path` |
| `photo/photos` | `photo_files` |

## 8. 准备度评分

申报准备度独立计算，不直接使用企业健康分。

```text
申报准备度 = Σ 单项得分 * 单项权重 / 权重总和
```

单项得分建议：

| 状态 | 分数建议 |
| --- | --- |
| 数量、字段、附件全部满足 | 100 |
| 数量满足，但字段或附件缺失 | 60-80 |
| 数量不足，但有部分资料 | 30-60 |
| 完全没有匹配资料 | 0 |

风险等级：

| 准备度 | 风险等级 |
| --- | --- |
| `>= 85` | `low` |
| `60-84` | `medium` |
| `< 60` | `high` |

## 11. 推荐开发顺序

### 阶段 1：数据库和基础模型

交付物：

- 4 张一期表 SQL。
- TypeORM Entity。
- `DatabaseModule` 注册。
- 后端 `npm run lint` 通过。

验收标准：

- SQL 可执行。
- 后端可以读写材料要求和检查结果。

### 阶段 2：客户端准备度检查后端

先不等后台配置页面，后端可内置一套默认材料要求，快速跑通检查逻辑。

交付物：

- `GET /client/projects/:id/material-readiness`
- `POST /client/projects/:id/material-check`
- 企业资料专表匹配服务。
- 准备度评分和风险等级。
- 检查结果保存。

验收标准：

- 指定项目能返回准备度。
- 能返回满足项、缺失项、补齐建议。
- 检查结果能落库。

### 阶段 3：客户端项目详情展示

交付物：

- 项目详情页展示准备度分数。
- 展示已满足、部分满足、缺失材料。
- 支持手动重新检查。

验收标准：

- 客户端进入项目详情能看到材料准备情况。
- 用户知道下一步要补哪些企业资料。

### 阶段 4：后台材料要求配置

交付物：

- 后台接口。
- 后台项目材料要求配置页面。
- 要求项新增、编辑、删除。
- 从默认模板生成要求。

验收标准：

- 管理员能维护项目材料要求。
- 客户端检查结果能使用后台配置。

### 阶段 5：申报创建联动

交付物：

- 创建申报草稿前自动检查材料。
- 必交项缺失时提醒。
- `biz_client_declaration.missing_material_count` 和检查结果联动。
- 申报详情展示材料检查结果。

验收标准：

- 用户创建申报时能看到缺失提醒。
- 申报列表能展示缺失材料数量。

### 阶段 6：申报材料快照

交付物：

- `biz_declaration_material_snapshot`
- 快照生成接口。
- 快照查询接口。
- 申报详情展示本次引用材料。

验收标准：

- 快照生成后不受企业资料后续变更影响。
- 能查看材料来源模块、来源记录和文件地址。

## 12. 第一期最小闭环

第一期优先交付下面内容：

1. `biz_project_material_requirement`
2. `biz_project_material_requirement_item`
3. `biz_declaration_material_check`
4. `biz_declaration_material_check_item`
5. `GET /client/projects/:id/material-readiness`
6. `POST /client/projects/:id/material-check`
7. 客户端项目详情展示准备度

快照和完整后台配置可以放到第二期。
