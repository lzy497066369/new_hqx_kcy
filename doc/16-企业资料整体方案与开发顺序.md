# 企业资料整体方案与开发顺序

## 1. 规划目标

企业资料模块是当前系统的主数据底座。后续政策匹配、项目申报、高企评分、材料准备度、申报书草稿和导出，都应从企业资料读取和引用数据。

本阶段先不改申报部分，优先把企业资料做扎实：

```text
企业资料负责维护主数据
申报项目负责查看、引用、测算、诊断和生成快照
```

核心目标：

- 企业基础信息、财税、人员、研发与知识产权、合同发票、制度文件、证书照片等资料在企业资料中统一维护。
- 财税、员工、知识产权等适合批量维护的资料支持 Excel 模板导入。
- RD、IP、PS、成果转化统一收敛到“研发与知识产权”大模块，形成高企申报证据链。
- 企业资料总览能展示健康分、关键指标、缺失项和下一步补齐入口。
- 申报模块后续只引用资料，不直接修改企业主数据。

## 2. 当前可用能力

当前系统已经具备企业资料主入口和多个资料专表，适合作为后续增强基础。

| 模块 | 当前可用情况 | 当前使用方式 |
| --- | --- | --- |
| 企业资料总览 | 有健康分、完整率、资料条数、附件条数、模块导航 | `/client/company` 查看资料完整度和待完善模块 |
| 基础信息 | 可维护企业名称、注册时间、技术领域、统一代码、地址、法人、联系人、资本、股东 | `/client/company/basic` 维护 |
| 联系人 | 支持企业联系人列表维护 | `/client/company/contacts` 维护 |
| 财税资料 | 有财务数据、纳税审计两类专表 | 手工新增年度财务数据和财税附件 |
| 员工资料 | 有员工花名册字段 | 手工维护人员、学历、职称、科研人员标识和附件 |
| 知识产权 | 有专利/软著基础清单 | 手工维护名称、类型、状态、编号、日期、获得方式、证书文件 |
| 科研项目 RD | 已在知识产权模块下作为科研项目维护 | 手工维护项目名称、编号、状态、时间、负责人、经费、立项报告 |
| 合同发票 | 有合同和发票两类记录 | 手工维护合同、发票、金额、日期和附件 |
| 制度文件 | 有制度文件专表 | 手工维护制度文件名称、分类、状态、版本、附件 |
| 企业证书/照片 | 有证书和照片图库 | 上传营业执照、资质、荣誉、场地、设备、产品照片 |
| 企业账号 | 有账号资料模块 | 维护高企、税务、知识产权等平台账号 |
| 材料模板中心 | 有模板下载和上传记录接口 | 当前还是内置占位模板，上传后只保存记录 |

## 3. 当前不足

企业资料已经有框架，但还没有达到“可支撑高企申报”的资料库程度。

| 问题 | 影响 |
| --- | --- |
| 材料模板还是占位 txt，不是真正 Excel 模板 | 财税、人员、IP 无法批量高效导入 |
| 上传材料只保存文件记录，不解析落库 | 上传财务表后不会自动进入财务专表 |
| 校验错误接口暂时返回空数组 | 用户不知道哪一行、哪个字段错了 |
| 财务字段偏基础 | 不足以完整支撑高企成长性、研发费用占比、高新收入占比 |
| 员工字段缺少身份证、部门、岗位、入职时间、社保等 | 高企科技人员证明材料不够完整 |
| IP 字段缺少 I/II 类、权利人、核心支持、关联 RD/PS | 高企知识产权评分依据不足 |
| RD 字段缺少高企申报说明字段 | 申报书 RD 活动表还需要大量补充 |
| PS 模块暂不存在 | 高新技术产品/服务只能后续临时填写，资料无法沉淀 |
| RD/IP/PS/成果转化没有关联关系 | 无法形成完整证据链 |
| 企业资料总览还偏完整度统计 | 缺少高企关键指标看板 |

## 4. 目标信息架构

建议把企业资料组织为下面 9 个一级模块。

| 一级模块 | 子模块 | 说明 |
| --- | --- | --- |
| 基础信息 | 企业信息、法人、联系人、资本、股东 | 企业主数据，申报只读引用 |
| 财税资料 | 财务数据、纳税审计、研发费用、高新收入 | 支撑成长性、研发投入、高新收入占比 |
| 人员资料 | 员工花名册、科技人员、证明附件、人员统计 | 支撑科技人员占比和人力资源表 |
| 研发与知识产权 | IP、RD、PS、成果转化、关联关系 | 高企创新能力核心资料 |
| 合同发票 | 合同、发票、收款、项目关联 | 支撑收入证明和成果转化证明 |
| 制度文件 | 研发制度、组织管理、成果转化、人才制度 | 支撑研发组织管理评分 |
| 企业证书 | 营业执照、资质、荣誉、体系认证 | 申报附件和企业资质证明 |
| 企业照片 | 场地、设备、产品、培训 | 申报附件和佐证资料 |
| 企业账号 | 高企、税务、知识产权、科技系统账号 | 方便项目老师协助操作 |

## 5. 研发与知识产权模块规划

RD、IP、PS 不建议分散到不同菜单。建议把现有“知识产权”升级为“研发与知识产权”，内部用 Tab 管理。

```text
研发与知识产权
  - 知识产权 IP
  - 研发项目 RD
  - 高新产品/服务 PS
  - 成果转化
  - 关联关系
```

### 5.1 知识产权 IP

当前已有基础字段，建议补齐高企评分口径。

| 字段方向 | 建议字段 |
| --- | --- |
| 基础信息 | IP 编号、名称、类型、登记号/专利号、状态、申请日期、授权日期 |
| 高企评分 | I/II 类、技术先进程度、核心支持程度、获得方式、是否参与标准 |
| 权属信息 | 权利人、发明人/著作权人、是否本企业权利人 |
| 关联关系 | 关联 RD、关联 PS、关联成果转化 |
| 附件 | 证书文件、受让协议、缴费证明、标准文件 |

### 5.2 研发项目 RD

RD 应作为企业资料长期沉淀，不应只在申报书里临时填写。

| 字段方向 | 建议字段 |
| --- | --- |
| 基础信息 | RD 编号、项目名称、项目状态、起止时间、负责人、技术领域 |
| 研发投入 | 预算、近三年支出、人员人工、直接投入、折旧摊销、设计费等 |
| 申报文本 | 目的及组织实施方式、核心技术及创新点、阶段性成果 |
| 关联关系 | 关联 IP、关联 PS、关联合同/发票、关联成果转化 |
| 附件 | 立项报告、研发记录、结题报告、检测报告、费用归集材料 |

### 5.3 高新产品/服务 PS

PS 建议新增为“研发与知识产权”下的子模块。

| 字段方向 | 建议字段 |
| --- | --- |
| 基础信息 | PS 编号、产品/服务名称、技术领域、技术来源 |
| 收入信息 | 上年度收入、高新收入口径、关联合同、关联发票 |
| 技术说明 | 关键技术、主要技术指标、竞争优势 |
| 关联关系 | 关联 RD、关联 IP、关联成果转化 |
| 附件 | 产品说明、销售合同、发票、检测报告、客户证明、照片 |

### 5.4 成果转化

成果转化用于连接“研发成果”和“收入/产品证明”。

| 字段方向 | 建议字段 |
| --- | --- |
| 基础信息 | 成果编号、成果名称、成果来源、转化年度、转化方式 |
| 转化对象 | 关联 RD、关联 IP、关联 PS |
| 证明材料 | 合同、发票、验收报告、检测报告、产品照片 |
| 经济效果 | 转化收入、客户名称、应用场景 |
| 申报说明 | 成果转化描述、技术成效、证明材料说明 |

### 5.5 关联关系

建议增加一个“关联关系”视图，不一定第一期就建复杂关系表，可以先用字段保存关联 ID。

目标效果：

```text
RD01 研发项目
  -> IP01/IP02 知识产权
  -> PS01 高新产品
  -> 成果转化 2024-01
  -> 合同/发票/检测报告
```

这能直接服务高企评分、材料准备度和申报书生成。

## 6. 财税资料规划

财税资料建议优先做导入闭环，因为高企评分和申报书都高度依赖三年财务数据。

### 6.1 当前可用

当前已有：

- `financial` 财务数据：年度、季度、销售收入、总资产、研发费用、负债、负债率、利润总额、备注。
- `taxAudit` 纳税审计：文件类型、税种/报告类别、年度、文件、备注。

### 6.2 建议补齐字段

| 类型 | 建议字段 |
| --- | --- |
| 财务数据 | 年度、净资产、总资产、负债、销售收入、主营业务收入、利润总额、净利润、研发费用、高新收入、总收入 |
| 研发费用 | 年度、人员人工、直接投入、折旧摊销、无形资产摊销、设计费、装备调试费、委托研发、其他费用 |
| 审计附件 | 年度、报告类型、审计机构、报告编号、文件附件 |
| 税务附件 | 年度、税种、申报期、文件附件 |

### 6.3 财税导入流程

```text
下载财税模板
  -> 企业填写三年财务数据/研发费用结构
  -> 上传 Excel
  -> 后端解析
  -> 字段校验
  -> 写入财税专表
  -> 生成错误行或导入结果
  -> 刷新企业资料健康分
```

第一版模板建议分 3 个 Sheet：

| Sheet | 内容 |
| --- | --- |
| 年度财务数据 | 近三年收入、资产、净资产、利润、研发费用、高新收入 |
| 研发费用结构 | 近三年研发费用明细 |
| 审计/税务附件清单 | 年度、报告类型、文件路径或上传说明 |

## 7. 人员资料规划

### 7.1 当前可用

当前已支持员工姓名、性别、员工类型、学历、职称、年龄段、是否科研人员、外籍/留学归国/千人计划、附件、备注。

### 7.2 建议补齐字段

| 类型 | 建议字段 |
| --- | --- |
| 基础身份 | 姓名、身份证号、性别、出生年月、年龄段 |
| 任职信息 | 部门、岗位、入职日期、员工类型、是否在职 |
| 高企口径 | 是否科技人员、参与 RD 项目、全年工作天数 |
| 学历职称 | 学历、专业、职称、职业资格 |
| 证明附件 | 劳动合同、社保、学历证明、职称证明 |

### 7.3 人员导入流程

```text
下载员工花名册模板
  -> 企业填写员工和科技人员信息
  -> 上传 Excel
  -> 校验身份证/学历/职称/科研人员标识
  -> 写入员工专表
  -> 自动统计科技人员占比
```

人员模块应自动输出：

| 指标 | 用途 |
| --- | --- |
| 职工总数 | 高企主要情况表 |
| 科技人员数 | 高企主要情况表和评分风险 |
| 科技人员占比 | 高企条件判断 |
| 学历结构 | 人力资源情况表 |
| 职称结构 | 人力资源情况表 |
| 年龄结构 | 人力资源情况表 |

## 8. 合同发票与成果证明规划

合同发票模块现在能维护合同和发票，但后续要和 PS、成果转化打通。

建议补齐：

| 模块 | 建议 |
| --- | --- |
| 合同 | 增加合同类型、关联 PS、关联成果转化、是否高新收入证明 |
| 发票 | 增加关联合同、关联 PS、收入年度、是否计入高新收入 |
| 收款 | 后续可增加收款日期、收款金额，用于收入证明闭环 |

合同和发票不建议放进 PS 模块里，但 PS 应能选择引用合同和发票。

## 9. 制度文件、证书照片、企业账号规划

### 9.1 制度文件

制度文件用于支撑研发组织管理评分。

建议分类：

| 分类 | 示例 |
| --- | --- |
| 研发组织管理 | 研发中心制度、研发项目管理制度 |
| 成果转化 | 成果转化制度、成果奖励制度 |
| 人才管理 | 科技人员培养、绩效、激励制度 |
| 财务核算 | 研发费用辅助账制度、费用归集制度 |
| 产学研合作 | 合作协议、共建平台文件 |

### 9.2 企业证书和照片

证书照片当前可用，建议继续作为附件库，不要和结构化表混在一起。

建议强化：

- 营业执照作为基础信息附件。
- 荣誉证书、资质证书、体系认证作为企业证书。
- 场地、设备、产品、培训照片作为申报附件。
- 所有文件可被 RD、PS、成果转化和申报材料引用。

### 9.3 企业账号

企业账号模块适合维护高企、科技、税务、知识产权等平台账号。建议增加“账号用途”和“可见权限”，避免敏感信息过度暴露。

## 10. 模板导入机制规划

现有材料模板中心应从“上传文件记录”升级为“模板解析和专表写入”。

### 10.1 模板类型

第一批建议做：

| 模板 | 优先级 | 写入模块 |
| --- | --- | --- |
| 财税数据模板 | P0 | 财税资料 |
| 员工花名册模板 | P1 | 人员资料 |
| 知识产权模板 | P2 | 研发与知识产权/IP |
| RD 研发项目模板 | P2 | 研发与知识产权/RD |
| PS 产品服务模板 | P3 | 研发与知识产权/PS |
| 成果转化模板 | P3 | 研发与知识产权/成果转化 |
| 合同发票模板 | P4 | 合同发票 |

### 10.2 导入状态

| 状态 | 说明 |
| --- | --- |
| `uploaded` | 已上传，等待解析 |
| `parsing` | 解析中 |
| `invalid` | 解析或校验失败 |
| `valid` | 校验通过并写入专表 |
| `partial` | 部分成功，部分行失败 |

### 10.3 错误反馈

导入失败必须返回可执行的错误：

| 字段 | 示例 |
| --- | --- |
| 行号 | 第 8 行 |
| 字段 | 年度 |
| 错误 | 年度不能为空 |
| 建议 | 请填写 2023、2024、2025 之一 |

## 11. 企业资料总览增强

企业资料总览应从“模块导航”升级成“申报资料仪表盘”。

建议展示：

| 区块 | 内容 |
| --- | --- |
| 资料健康分 | 当前已有，继续保留 |
| 高企关键指标 | 职工总数、科技人员占比、IP 数量、RD 数量、PS 数量、成果转化数量 |
| 财税关键指标 | 三年销售收入、净资产、研发费用、高新收入 |
| 缺失项 | 按模块列出缺什么资料 |
| 快捷入口 | 去补财税、去导入员工、去维护研发与知识产权 |
| 最近导入 | 展示最近模板上传、解析结果和错误数 |

## 13. 开发顺序

### P0：财税导入闭环

目标：先解决高企最依赖的三年财务数据。

任务：

| 顺序 | 任务 |
| --- | --- |
| 1 | 定正式财税导入模板，第一版使用 Excel 可打开的 CSV |
| 2 | 扩展财务数据字段 |
| 3 | 上传后解析 CSV，后续可升级为原生 xlsx 解析 |
| 4 | 校验年度、金额、必填项 |
