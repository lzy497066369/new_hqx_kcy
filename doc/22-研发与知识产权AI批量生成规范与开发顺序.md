# 研发与知识产权 AI 批量生成规范与开发顺序

## 1. 规划目标

本规范用于指导客户端企业资料中“研发与知识产权”模块的下一阶段升级。

现有模块已经具备 4 个核心 Tab：

```text
知识产权 IP
成果转化
研发项目 RD
高新产品/服务 PS
```

本阶段目标不是新增独立 AI 页面，而是在现有“研发与知识产权”页面中增加批量上传、AI 识别、AI 生成、人工审核和批量入库能力。

推荐主链路：

```text
知识产权 PDF 批量上传
  -> AI/OCR 识别知识产权内容
  -> 人工审核后批量写入知识产权
  -> 按知识产权批量生成成果转化
  -> 选择知识产权和研发时间生成 RD 立项报告
  -> 按 RD 领域聚合生成 PS 高新产品/服务
```

核心原则：

- AI 只生成草稿，不直接写入正式业务主表。
- 所有 AI 识别和生成结果必须经过人工审核确认。
- 每一步都要保留来源关系，形成 IP、成果转化、RD、PS 的证据链。
- 批量操作必须支持预览、编辑、勾选、跳过和失败重试。
- 优先服务高企申报口径，字段设计要能支撑后续评分、材料准备度和申报书草稿。

## 2. 现有入口

前端入口：

```text
vue-admin/apps/web-client/src/views/client/enterprise-profile/property/index.vue
```

路由入口：

```text
vue-admin/apps/web-client/src/router/routes/modules/client.ts
```

当前页面能力：

| Tab | 当前能力 | 本次升级方向 |
| --- | --- | --- |
| 知识产权 | 手工新增、编辑、删除、导入模板 | PDF 批量上传识别、批量审核入库 |
| 成果转化 | 手工新增、编辑、删除 | 基于全部知识产权批量生成成果草稿 |
| 研发项目 RD | 手工维护 RD 资料和关联关系 | 选择 IP 和研发时间，AI 生成立项报告 |
| 高新产品 PS | 手工维护 PS 资料和关联关系 | 拉取所有 RD，按领域自动聚合生成 PS |

## 3. 总体业务闭环

### 3.1 数据流

```text
企业上传知识产权 PDF
  -> 保存 PDF 附件
  -> 进入识别任务
  -> 生成知识产权识别草稿
  -> 用户审核确认
  -> 写入知识产权正式表
  -> 生成成果转化草稿
  -> 用户审核确认
  -> 写入成果转化正式表
  -> 选择 IP 和研发周期
  -> 生成 RD 立项报告草稿
  -> 用户审核确认
  -> 写入 RD 正式表
  -> 汇总 RD、IP 和领域
  -> 生成 PS 草稿
  -> 用户审核确认
  -> 写入 PS 正式表
```

### 3.2 审核状态

建议所有 AI 结果统一使用草稿状态管理。

| 状态 | 含义 | 可操作 |
| --- | --- | --- |
| `pending` | 等待处理 | 可取消 |
| `processing` | 识别或生成中 | 只读 |
| `reviewing` | 等待人工审核 | 可编辑、确认、退回 |
| `approved` | 已确认入库 | 只读，可查看来源 |
| `rejected` | 已退回 | 可删除、重新生成 |
| `failed` | 处理失败 | 可查看失败原因、重试 |

## 4. 第一步：知识产权 PDF 批量识别

### 4.1 入口改造

在“知识产权”Tab 中，将原有“添加知识产权”扩展为两个入口：

| 入口 | 用途 |
| --- | --- |
| 手工新增 | 保留原来的单条录入能力 |
| 上传识别知识产权 | 新增 PDF 批量上传识别流程 |

“上传识别知识产权”建议使用抽屉或弹窗，不跳出当前页面。

### 4.2 上传交互

上传区域要求：

- 支持拖拽 PDF 到上传区域。
- 支持点击选择一个或多个 PDF。
- 支持展示文件名、大小、上传进度、识别状态。
- 限制文件类型为 PDF。
- 单文件大小限制建议第一期设置为 20MB。
- 单次上传数量建议第一期设置为 20 个。
- 上传后先保存附件，再触发识别任务。

上传列表字段：

| 字段 | 说明 |
| --- | --- |
| 文件名 | 原始 PDF 文件名 |
| 文件大小 | 便于判断异常文件 |
| 上传状态 | 上传中、上传成功、上传失败 |
| 识别状态 | 等待识别、识别中、识别完成、识别失败 |
| 失败原因 | OCR 失败、AI 解析失败、文件损坏等 |
| 操作 | 查看文件、重新识别、移除 |

### 4.3 AI/OCR 识别字段

知识产权识别结果至少包含：

| 字段 | 说明 | 是否必填 |
| --- | --- | --- |
| 知识产权名称 | 专利名称、软著名称、商标名称等 | 是 |
| 知识产权类型 | 发明专利、实用新型、外观设计、软件著作权、商标等 | 是 |
| 证书编号 | 专利号、登记号、证书号 | 是 |
| 权利人 | 企业名称或权利人列表 | 是 |
| 申请日期 | PDF 中可识别则填入 | 否 |
| 授权日期/登记日期 | PDF 中可识别则填入 | 否 |
| 获得方式 | 自主研发、受让、并购、独占许可等 | 否 |
| IP 类别 | I 类、II 类 | 否 |
| 法律状态 | 有效、授权、登记、失效等 | 否 |
| 摘要说明 | 从证书或文本中提炼的技术摘要 | 否 |
| 证书附件 | 原 PDF 附件 ID 或 URL | 是 |
| 识别置信度 | 0 到 100 | 否 |

### 4.4 审核列表

识别完成后进入“识别结果审核列表”。

列表要求：

- 每个 PDF 对应一条或多条识别草稿。
- 支持表格内编辑识别字段。
- 支持勾选需要入库的记录。
- 支持逐条查看原 PDF。
- 支持标记“无效文件”或“暂不入库”。
- 支持重复检测提示。
- 支持批量确认写入正式知识产权。

重复检测规则：

| 判断项 | 处理方式 |
| --- | --- |
| 证书编号已存在 | 强提示，默认不勾选 |
| 名称和权利人高度相似 | 弱提示，允许用户确认 |
| 同一 PDF 重复上传 | 提示已上传过，可查看历史 |

### 4.5 入库规则

点击“批量审核通过并添加到系统”后：

- 已勾选且校验通过的草稿写入知识产权正式表。
- 原 PDF 作为证书附件关联到知识产权。
- 草稿状态改为 `approved`。
- 校验失败的记录留在审核列表，不影响其他记录入库。
- 入库后刷新知识产权列表和证据链统计。

### 4.6 验收标准

| 项目 | 标准 |
| --- | --- |
| 多文件上传 | 一次可上传多个 PDF |
| 拖拽上传 | 拖入 PDF 后能进入上传队列 |
| 识别结果 | 至少能生成名称、类型、编号、权利人、附件 |
| 人工审核 | 入库前可编辑、勾选、删除 |
| 批量入库 | 多条知识产权可一次确认写入 |
| 失败处理 | 单个文件失败不影响其他文件 |
| 证据保留 | 正式记录能查看原 PDF 附件 |

## 5. 第二步：成果转化批量生成

### 5.1 入口改造

在“成果转化”Tab 增加：

```text
按知识产权批量生成成果
```

点击后打开批量生成抽屉。

### 5.2 数据来源

生成前拉取当前企业所有知识产权。

默认过滤：

- 已正式入库的知识产权。
- 状态有效或可用于申报的知识产权。
- 未生成过成果转化，或允许再次生成的知识产权。

可选开关：

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 包含已生成成果的 IP | 关闭 | 避免重复生成 |
| 仅核心知识产权 | 关闭 | 后续有核心标记后启用 |
| 按授权年度分组 | 关闭 | 用于申报年度归集 |

### 5.3 生成规则

每个知识产权默认生成一条成果转化草稿。

每条草稿包含：

| 字段 | 生成方式 |
| --- | --- |
| 成果名称 | 根据知识产权名称生成应用化成果名称 |
| 成果内容 | 描述该知识产权形成的技术成果、应用场景和转化价值 |
| 技术内容/技术描述 | 描述核心技术、解决问题、创新点和技术效果 |
| 关联知识产权 | 自动关联当前 IP |
| 转化年度 | 优先取授权日期年份，否则由用户批量选择 |
| 转化方式 | 默认“自行实施”或由用户选择 |
| 证明材料说明 | 提示后续可补合同、发票、验收、产品照片等 |

AI 生成要求：

- 成果名称要像成果，不要直接复制知识产权名称。
- 成果内容要体现“从技术到应用”的转化过程。
- 技术内容要突出核心技术和效果，避免空泛宣传。
- 不编造合同、收入、客户和发票。
- 缺少事实依据时用待补充描述，不生成虚假信息。

### 5.4 审核和入库

审核列表要求：

- 展示知识产权名称、成果名称、成果内容、技术内容、转化年度、转化方式。
- 支持表格内编辑。
- 支持批量设置转化年度和转化方式。
- 支持勾选后批量入库。
- 支持查看每条成果来源的知识产权。

入库后：

- 写入成果转化正式表。
- 保存成果和知识产权关联关系。
- 刷新成果转化列表。
- 证据链中可看到 `IP -> 成果转化`。

### 5.5 验收标准

| 项目 | 标准 |
| --- | --- |
| 拉取 IP | 能显示当前企业所有可用知识产权 |
| 一 IP 一成果 | 默认每个知识产权生成一条成果草稿 |
| 内容可编辑 | 成果名称、成果内容、技术描述都可人工修改 |
| 批量保存 | 勾选多条后可一次写入成果转化 |
| 关系保存 | 成果正式记录能回溯关联知识产权 |
| 重复提示 | 已有关联成果的 IP 需要提示 |

## 6. 第三步：RD 研发项目立项报告生成

### 6.1 入口改造

在“研发项目 RD”Tab 中，将新增入口扩展为：

| 入口 | 用途 |
| --- | --- |
| 手工新增 RD | 保留现有能力 |
| 新增研发项目并生成立项报告 | 选择知识产权和研发时间后 AI 生成 |

### 6.2 用户输入

新增 RD 生成前，用户至少需要填写：

| 字段 | 说明 | 是否必填 |
| --- | --- | --- |
| 关联知识产权 | 可多选 IP | 是 |
| 研发开始时间 | 用于生成周期计划 | 是 |
| 研发结束时间 | 用于生成周期计划 | 是 |
| 技术领域 | 可手选，也可由 AI 根据 IP 推荐 | 建议必填 |
| 研发负责人 | 可选 | 否 |
| 预算金额 | 可选 | 否 |
| 补充说明 | 用户补充研发背景、目标、产品方向 | 否 |

### 6.3 AI 生成内容

AI 输出 RD 草稿，建议字段如下：

| 字段 | 说明 |
| --- | --- |
| RD 编号 | 可由系统生成，如 RD2026-001 |
| 研发项目名称 | 根据知识产权、技术领域和研发目标生成 |
| 项目背景 | 说明行业背景、企业需求和技术痛点 |
| 立项目的 | 说明为什么要开展该研发项目 |
| 研发目标 | 明确研发完成后要达到的技术或产品目标 |
| 主要研究内容 | 拆分 3 到 6 项具体研究内容 |
| 技术路线 | 描述从需求、设计、开发、测试到应用的路径 |
| 创新点 | 结合关联 IP 提炼创新性 |
| 研发周期计划 | 按用户选择的起止时间拆阶段 |
| 预期成果 | 说明可形成的 IP、产品、样机、报告、标准等 |
| 关联知识产权说明 | 说明选中 IP 如何支撑该 RD |
| 费用预算说明 | 有预算时生成结构说明，无预算时生成待补充草稿 |
| 人员组织说明 | 有负责人时结合负责人生成，无负责人时生成通用草稿 |
| 立项报告正文 | 可用于附件或申报书草稿的完整文本 |

### 6.4 审核和保存

保存前要求：

- 用户可编辑所有 AI 生成字段。
- 用户必须确认关联知识产权。
- 研发开始时间不能晚于结束时间。
- 项目名称不能为空。
- 立项报告正文可保存为文本字段，也可后续导出为附件。

保存后：

- 写入 RD 正式表。
- 保存 RD 与 IP 的关联关系。
- 可在证据链中显示 `RD -> IP`。
- 后续成果转化和 PS 生成可引用该 RD。

### 6.5 验收标准

| 项目 | 标准 |
| --- | --- |
| 选择 IP | 新增 RD 前可多选知识产权 |
| 时间输入 | 必须选择研发起止时间 |
| AI 生成 | 能生成项目名称和完整立项报告 |
| 人工编辑 | 生成内容可编辑后保存 |
| 关系保存 | RD 正式记录能关联 IP |
| 证据链展示 | 页面能看到 RD 关联的 IP |

## 7. 第四步：PS 高新产品批量生成

### 7.1 入口改造

在“高新产品 PS”Tab 增加：

```text
按 RD 批量生成 PS
```

点击后打开 PS 批量生成抽屉。

### 7.2 数据来源

生成前拉取：

- 当前企业所有 RD 研发项目。
- 每个 RD 关联的知识产权。
- RD 的技术领域、关键词、研发名称、核心技术和成果。
- 已有 PS 记录，用于重复检测。

### 7.3 分组规则

系统根据不同研发项目的领域分出不同 PS。

建议第一期规则：

| 规则 | 说明 |
| --- | --- |
| 技术领域相同 | 优先归为同一组 |
| RD 名称关键词相近 | 作为辅助分组依据 |
| 关联 IP 名称相近 | 作为辅助分组依据 |
| 用户手动调整 | 支持把 RD 移到其他 PS 草稿组 |

后续增强：

- AI 自动识别 RD 所属产品方向。
- AI 判断多个 RD 是否支撑同一个产品或服务。
- 支持拆分、合并 PS 草稿。

### 7.4 PS 名称生成规则

PS 名称应根据同一领域下所有 RD 和 IP 名称综合生成。

要求：

- 名称要像高新技术产品或服务名称。
- 不直接使用单个 RD 项目名称。
- 不直接堆叠所有 IP 名称。
- 尽量体现产品形态、服务对象或技术方向。
- 可生成 3 个候选名称供用户选择。

示例：

```text
RD：
- 智能数据采集算法研发
- 企业风险识别模型研发

IP：
- 一种企业数据画像分析系统
- 企业政策匹配软件

PS 候选名称：
- 企业智能数据分析服务平台
- 企业政策匹配与风险识别系统
- 面向企业服务的数据画像分析产品
```

### 7.5 PS 草稿字段

每个 PS 草稿包含：

| 字段 | 说明 |
| --- | --- |
| PS 编号 | 可由系统生成，如 PS2026-001 |
| 产品/服务名称 | 根据 RD 和 IP 综合生成 |
| 技术领域 | 来自 RD 分组或用户选择 |
| 技术来源 | 自主研发、合作研发等 |
| 关键技术 | 汇总 RD 和 IP 中的核心技术 |
| 主要技术指标 | AI 生成草稿，用户确认 |
| 竞争优势 | 根据 RD 创新点和 IP 支撑生成 |
| 关联 RD | 自动关联分组内 RD |
| 关联 IP | 自动汇总关联 RD 下的 IP |
| 关联成果转化 | 能匹配则自动关联，否则提示待补 |
| 收入说明 | 不编造金额，只生成待补充说明 |
| 证明材料说明 | 提示合同、发票、检测报告、产品照片等 |

### 7.6 审核和保存

审核列表要求：

- 左侧展示 PS 草稿列表。
- 右侧展示当前 PS 关联的 RD、IP 和成果。
- 支持编辑 PS 名称、领域、关键技术、技术指标、竞争优势。
- 支持调整 RD 分组。
- 支持合并或拆分 PS 草稿。
- 支持勾选后批量保存。

保存后：

- 写入 PS 正式表。
- 保存 PS 与 RD、IP、成果转化的关联关系。
- 刷新 PS 列表。
- 证据链中可显示 `PS -> RD -> IP -> 成果转化`。

### 7.7 验收标准

| 项目 | 标准 |
| --- | --- |
| 拉取 RD | 能显示当前企业所有 RD |
| 自动分组 | 能按技术领域生成 PS 草稿组 |
| 名称生成 | PS 名称根据组内 RD 和 IP 综合生成 |
| 用户调整 | 用户可修改名称、字段和 RD 分组 |
| 批量保存 | 多个 PS 草稿可批量写入 |
| 关系保存 | PS 正式记录能关联 RD、IP、成果 |

## 8. 后端接口规划

### 8.1 知识产权 PDF 识别

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/client/enterprise/property/ip-recognition/uploads` | 上传一个或多个 PDF |
| `POST` | `/client/enterprise/property/ip-recognition/tasks` | 创建识别任务 |
| `GET` | `/client/enterprise/property/ip-recognition/tasks/:id` | 查询识别任务状态 |
| `GET` | `/client/enterprise/property/ip-recognition/drafts` | 查询识别草稿列表 |
| `PATCH` | `/client/enterprise/property/ip-recognition/drafts/:id` | 修改识别草稿 |
| `POST` | `/client/enterprise/property/ip-recognition/approve` | 批量确认入库 |
| `POST` | `/client/enterprise/property/ip-recognition/retry` | 批量重新识别 |

### 8.2 成果转化批量生成

## 12. 开发顺序

本章节作为实际开发排期依据。开发时按 `P0 -> P1 -> P2 -> P3 -> P4 -> P5` 推进，不建议跳过 P0 直接做页面，因为后续四个业务步骤都依赖统一草稿、任务状态、附件和关联关系。

每个阶段都按同一套落地节奏执行：

```text
字段和 SQL
  -> 后端实体和 DTO
  -> 后端接口和服务
  -> 前端 API 类型
  -> 前端弹窗/抽屉/审核表
  -> 联调和失败态
  -> 验收记录
```

阶段放行规则：

| 放行项 | 要求 |
| --- | --- |
| 数据结构 | SQL、Entity、DTO 字段一致，不出现只在前端存在的字段 |
| 接口闭环 | 每个生成流程必须具备创建任务、查询任务、查询草稿、编辑草稿、确认入库 |
| 审核闭环 | AI 结果只进入草稿，不绕过人工审核直接写主表 |
| 关系闭环 | 正式记录入库时同步保存来源关系 |
| 失败闭环 | 上传失败、AI 失败、部分入库失败都有明确提示和可重试路径 |
| 验证闭环 | 后端 lint、前端 typecheck 通过，关键接口可用 |

目标：确认现有 IP、成果、RD、PS 字段是否够用。

任务：

| 序号 | 内容 |
| --- | --- |
| 1 | 准备一组真实或脱敏 PDF、IP、RD、成果、PS 验收数据 |
| 2 | 跑通 `PDF -> IP -> 成果 -> RD -> PS -> 证据链` 全链路 |

- 可用真实或模拟数据完整跑通一条企业资料链路。

- 可先运行 `npm run verify:client-property-ai -- --audit-implementation` 验证文档、SQL、后端接口、前端 API 和页面组件覆盖情况，再运行 `npm run verify:client-property-ai -- --audit-schema` 只读验证当前开发库关键表和字段，随后运行 `npm run verify:client-property-ai -- --sample` 验证脚本逻辑，之后用 `--list-enterprises` 查找候选企业，最后用真实企业 ID 验证当前库数据。

### 联调数据顺序

联调不要一开始就使用大量真实 PDF，先用最小数据集跑通关系。

### 不建议第一期做的内容

为了控制范围，下面内容建议后置：

| 内容 | 后置原因 |
| --- | --- |
| 自动生成申报书完整章节 | 依赖证据链稳定后再做，避免生成内容不可控 |
| 自动判断所有 RD 和 PS 最优合并方案 | 需要更多业务样本校准 |
| 自动编造收入、合同、客户、发票 | 高企申报风险高，必须由真实材料支撑 |
| 复杂知识图谱可视化 | 第一阶段用列表和缺口提示即可 |
| 完全无人工审核入库 | 与本模块风控原则冲突 |

## 14. 风险和边界

| 风险 | 处理方式 |
| --- | --- |
| PDF 内容扫描质量差 | 标记低置信度，要求人工补录 |
| AI 编造不存在的事实 | 提示词限制，不允许生成合同、收入、客户等事实 |
| 重复生成数据 | 增加编号、名称、关联关系重复检测 |
| 批量入库部分失败 | 使用逐条结果，不回滚成功记录，失败项保留 |
| AI 接口耗时较长 | 使用任务状态轮询，前端显示处理中 |
| 数据字段不够 | P0 先确认字段，必要时补 SQL |
| 关系复杂 | 第一阶段先保存关键关联，后续再做完整关系图谱 |

## 15. 最小可上线版本

如果需要尽快上线，建议压缩为下面范围：

| 阶段 | 必做 | 可后置 |
| --- | --- | --- |
| 知识产权 | PDF 上传、识别草稿、人工审核入库 | 高级重复检测、置信度可视化 |
| 成果转化 | 按 IP 生成成果名称、内容、技术描述 | 批量年度智能推断 |
| RD | 选择 IP 和时间生成立项报告 | 预算和人员结构自动生成 |
| PS | 按 RD 技术领域生成 PS 草稿 | AI 自动合并拆分复杂分组 |
| 证据链 | 显示 IP、成果、RD、PS 基础关联 | 完整图谱和评分联动 |

最小上线闭环：

```text
上传 IP PDF
  -> 审核入库
  -> 批量生成成果
  -> 生成 RD 立项报告
  -> 批量生成 PS
  -> 查看基础证据链
```

## 16. 最终验收标准

| 编号 | 验收项 | 标准 |
| --- | --- | --- |
| 1 | 知识产权 PDF 批量识别 | 多个 PDF 可识别、审核、批量入库 |
| 2 | 成果转化批量生成 | 所有 IP 可生成成果名称、成果内容、技术描述 |
| 3 | RD 立项报告生成 | 选择 IP 和研发时间后可生成完整立项报告 |

| 5 | 人工审核 | AI 结果入库前必须可人工编辑确认 |
| 6 | 关系保存 | IP、成果、RD、PS 之间关联完整 |
| 7 | 失败处理 | 单条失败不影响整体批量流程 |
| 8 | 审计记录 | AI 生成来源、确认人、确认时间可追溯 |
| 9 | 页面体验 | 所有流程都在研发与知识产权页面内完成 |
| 10 | 高企支撑 | 生成结果可用于高企证据链、评分和申报书草稿 |
