# 统一企业服务中心重构规划

## 1. 目标与决策

本次改造不是把 `web-client` 的页面复制到 `web-admin`，而是在后台管理系统中建设一个以企业为中心的工作台，将企业资料、申报、材料准备度、项目协同和审核处理组织成同一条业务链路。

统一后的系统仍按角色展示不同能力：

| 角色 | 可见企业范围 | 核心动作 |
| --- | --- | --- |
| 平台管理员 | 全部企业 | 分配项目老师、维护资料、配置项目、审核和统计 |
| 项目老师 | 已绑定企业 | 补齐资料、诊断、发起或推进申报、处理补正 |
| 企业经办人 | 自己绑定企业 | 在客户端提供资料、处理补正、确认申报内容 |

企业服务中心只面向平台管理员和项目老师；企业经办人继续使用客户端自助入口，不显示后台企业列表、企业档案或审核能力。后台与客户端共用企业资料数据模型，但不能共用“当前客户端账号”语义。管理员和项目老师访问企业数据时，企业 ID 必须体现在 URL 和接口中；企业经办人仍由绑定关系解析可访问企业。

## 2. 重构原则

1. 以企业为入口，而不是以客户端菜单为入口。所有资料、申报和待办都必须明确归属到某家企业。
2. 企业主数据只在企业档案维护；申报页只引用、诊断和提交，不直接编辑财税、人员或知识产权主数据。
3. 材料台账默认聚合当前账号可见企业的资料，可用公司筛选缩小范围；仅编辑、审核等行级动作才显式携带对应 `enterpriseId`。不复用现有仅限 `client` 门户的 `/client/*` 接口，也不删除 `PortalGuard`。
4. 后台页面按管理员和项目老师任务重组，保留数据与规则，不保留客户端的首页、公司切换页、独立政策库等页面壳。
5. 所有跨企业写操作记录操作者、目标企业、来源页面和变更摘要，方便追溯。

## 3. 目标信息架构

```text
企业服务中心（一级目录）
  企业列表
  企业材料台账（默认跨企业聚合，公司筛选）
  企业工作台
    企业概览
    待办与风险
    项目老师协同
  企业档案
    基础信息与联系人
    财税资料
    人员资料
    研发与知识产权（IP / RD / PS / 成果转化 / 证据链）
    合同发票、制度文件、证书照片、企业账号
  申报工作台
    可申报项目
    进行中申报
    申报详情（准备度、评分、材料、时间线、草稿）
  审核与协同
    补正任务
    审核记录
    通知与操作日志
```

页面采用后台工作台风格：企业选择器始终可见、列表支持筛选与批量操作、详情页提供明确的上下文和状态；不将企业用户的“去补全”“我的公司”等文案直接带入管理端。

## 4. 客户端能力去向

| 原客户端能力 | 统一后的后台位置 | 处理方式 |
| --- | --- | --- |
| 首页、数据分析、待办 | 企业工作台 | 后台只保留企业概览、风险和待办；客户端继续保留企业用户自助待办 |
| 公司切换 | 顶部企业选择器和企业列表 | 仅后台角色使用，改为 URL 中的 `enterpriseId`，不保存管理员的全局当前企业 |
| 个人情况、企业用户 | 系统管理、企业成员 | 后台维护企业成员和绑定关系；企业用户个人页仍在客户端 |
| 基础信息、联系人 | 企业档案 | 按企业详情页的分区维护 |
| 财税、人员、研发与知识产权 | 企业档案 | 保留导入、AI 解析、批量生成和证据链能力 |
| 合同发票、制度文件、证书照片、企业账号 | 企业档案 | 以附件、记录和业务关联方式聚合 |
| 政策库 | 政策管理 + 企业项目匹配 | 管理员看全量政策；企业工作台只展示与当前企业匹配的项目 |
| 项目列表、我的申报、申报详情 | 申报工作台 | 以“候选项目 / 进行中申报 / 审核队列”组织 |
| 客户端专属通知 | 审核与协同 | 按待办、补正、审核结果进入统一通知中心 |

## 5. 页面与组件边界

第一期新增的路由级页面只承担数据编排，不堆积表单细节：

| 页面/组件 | 职责 | 关键输入输出 |
| --- | --- | --- |
| `enterprise/list.vue` | 搜索、筛选和进入企业 | 输出选中的 `enterpriseId` |
| `enterprise/workspace/index.vue` | 企业概览、风险和待办的组合 | 输入路由 `enterpriseId` |
| `enterprise/profile/index.vue` | 企业档案的导航与摘要 | 输入 `enterpriseId`，子页按模块加载 |
| `enterprise/profile/*` | 一个资料域的查询、编辑或导入 | 输入 `enterpriseId`，保存后发出刷新事件 |
| `declaration/workspace.vue` | 候选项目、进行中申报和审核队列 | 输入 `enterpriseId` 或全局筛选条件 |
| `declaration/detail.vue` | 准备度、评分、草稿和时间线 | 输入 `declarationId`，资料跳转保留企业上下文 |
| `useEnterpriseContext.ts` | 解析路由企业、加载摘要、提供跳转 | 返回只读企业状态和显式跳转方法 |

复杂的资料表格、导入弹窗、AI 草稿弹窗继续拆为领域组件；路由页不直接维护跨模块的可变状态。

## 6. 后端边界

新增管理端资源组，建议统一使用 `/enterprise-workspace`，并通过权限和企业范围校验访问：

| 接口组 | 示例 | 用途 |
| --- | --- | --- |
| 企业上下文 | `GET /enterprise-workspace/enterprises`、`GET /enterprise-workspace/enterprises/:id/summary` | 列表、摘要、权限范围 |
| 企业档案 | `GET/PUT /enterprise-workspace/enterprises/:id/profile` | 基础信息、联系人及资料分区 |
| 企业资料记录 | `GET/POST/PUT /enterprise-workspace/enterprises/:id/records/:module/:tab` | 财税、人员、IP、RD、PS、合同、制度等 |
| 材料与附件 | `POST /enterprise-workspace/enterprises/:id/materials` | 上传、校验、预览、下载 |
| 企业申报 | `GET/POST /enterprise-workspace/enterprises/:id/declarations` | 候选项目、创建草稿、列表和详情 |
| 审核协同 | `POST /enterprise-workspace/declarations/:id/reviews` | 审核、退回、补正、操作记录 |

接口必须先执行 `EnterpriseScopeService.assertAccessible(currentUser, enterpriseId, action)`：平台管理员按权限访问全量企业，项目老师仅限绑定企业。企业经办人不访问企业服务中心，继续由客户端绑定关系校验。写操作增加 `OperationLog`，日志包含目标企业和申报 ID。

现有 `/client/*` 保持企业自助场景使用，不新增 `admin` 到该路由的放行规则；两套接口可复用底层领域服务和 DTO 映射，但不共用身份解析。

## 7. 实施阶段

### P0：统一企业上下文与工作台骨架

- 建立企业服务中心路由、企业选择器和 `enterpriseId` URL 规范。
- 新增企业摘要、待办和风险的管理端查询接口。
- 在企业列表中进入企业工作台；项目老师只能看到已绑定企业。
- 验收：刷新页面后企业上下文不丢失；直接修改 URL 无法越权访问其他企业。

### P1：企业档案重组

- 将现有企业资料按 9 个领域组织到后台企业详情。
- 首先完成基础信息、联系人、财税、人员四个高频模块。
- 保留导入、解析和校验结果，但改为后台表格、抽屉和详情工作流。
- 验收：管理员可从企业工作台进入资料域，资料变更可追溯到企业和操作者。

#### P1-A 实施记录：基础信息与联系人

- 已提供后台专用的企业基础信息和联系人 CRUD 接口，所有路由显式携带 `enterpriseId`。
- 已接入企业档案页面，支持维护基础信息、默认联系人和申报协同联系人。
- 操作日志优先读取 `enterpriseId` 作为业务目标，并将 `/enterprise-workspace/*` 标识为“企业服务中心”。
- 后续继续接入财税和人员资料域，不复用客户端的当前企业接口。

#### P1-B 实施记录：财税资料

- 已提供年度财税记录的后台专用查询、新增、编辑和删除接口，覆盖营业收入、净利润、净资产、研发费用、高新收入及资产负债等核心字段。
- 企业工作台已接入年度财税资料页，管理员和项目老师可在明确企业上下文中维护记录。
- 财税资料写操作保留原有企业范围校验与操作日志归属，不调用客户端专用接口。

#### P1-C 实施记录：人员资料名册

- 已提供员工名册查询及新增、编辑、删除接口，覆盖姓名、部门、职位、在职状态、科技人员、学历/职称代码、入职信息和 RD 参与信息。
- 企业工作台已接入员工统计和名册维护页面，员工总数、在职人数和科技人员数随数据刷新。
- 已接入员工 Excel 模板下载和“上传、预览、确认入库”流程，支持重复识别、错误提示和逐行跳过；确认后更新员工统计与资料完整度。
- 解析和入库规则复用领域服务，但后台接口始终显式携带 `enterpriseId`，不开放客户端身份语义或复制客户端页面结构。

#### P1-D 实施记录：档案附件与业务凭据

- 已将合同、发票、制度文件、企业证书和企业账号聚合到后台企业档案资料页，支持在固定企业上下文中新增、编辑、删除。
- 所有资料域操作均经过企业范围校验并写入企业服务中心操作日志；企业账号密码不出现在列表或读取接口，编辑时留空会保持原值。
- 已增加后台菜单路由和可重复执行的 `sys_menu` 补丁，详情页保持隐藏，仅从企业工作台或企业资料入口进入。

### P2：研发知识产权与证据链

- 接入 IP、RD、PS、成果转化和关联证据链。
- 将 AI 批量生成改为“生成 - 草稿审核 - 入库”三步流程。
- 验收：任何草稿、生成任务和记录都可回溯到企业资料域。

#### P2-A 实施记录：知识产权名册

- 已接入后台知识产权名册的查询、新增、编辑和删除，覆盖名称、类别、状态、登记/专利号、权利人、授权信息和核心 IP 标识。
- 管理端通过企业工作台进入该资料域；接口显式携带 `enterpriseId` 并复用企业范围校验。
- 后续在此主数据基础上接入 RD、PS、成果转化及证据链关联。

#### P2-B 实施记录：RD 研发项目名册

- 已提供 RD 研发项目的后台查询、新增、编辑和删除接口，覆盖项目名称、编号、状态、周期、负责人、项目类型、经费和核心技术。
- 管理端已新增研发项目名册页，企业工作台上下文由 URL 中的 `enterpriseId` 固定。
- 知识产权、PS、成果转化的关系字段将以明确的数组映射协议接入，避免把临时文本格式作为跨资料关联契约。

#### P2-C 实施记录：IP-RD-PS-成果转化证据链

- 已接入 PS 产品服务与成果转化名册，并支持维护 IP、RD、PS 三类关联 ID。
- 已新增证据链总览接口和管理端页面，按 IP、RD、PS、成果转化汇总节点、有效关联与断链项；失效或跨企业 ID 不计入有效关联。
- 断链规则覆盖：IP 未关联 RD、RD 缺 IP、PS 缺 IP 或 RD、成果转化缺 IP/RD/PS；工作台同时聚合为风险项。
- 已补充 `enterprise-workspace-menu-p1.sql`，动态 `enterpriseId` 详情页进入后台菜单树但保持隐藏，企业资料列表仍是可见入口。

### P3：申报工作台与审核闭环

- 把项目匹配、可申报项目、进行中申报、准备度和材料清单放到一个工作台。
- 申报详情引用企业资料；缺项跳转对应资料域；审核退回生成待办。
- 验收：从项目匹配到补资料、提交、审核和补正全链路可完成。

#### P3-A 实施记录：企业申报工作台

- 已按企业档案省、市、区匹配已发布政策和项目，候选项目会显示截止时间、匹配政策数量、申报方案资格缺口和已有进行中申报。
- 已支持从候选项目创建后台申报草稿，草稿显式归属 `enterpriseId` 并保存政策、方案版本和来源快照。
- 申报详情已汇总材料准备度、缺项建议、补正原因与流程历史；审核人可通过或退回，退回后生成企业工作台风险并进入补正链路。

### P4：通知、统计与客户端收口

- 已在企业资料列表顶部接入企业服务中心组合统计，包含可见企业、资料待完善、材料待补、审核中、临期申报和证据链断链。
- 统计接口为 `GET /enterprise-workspace/overview`，管理员聚合全部企业，项目老师仅聚合已绑定企业；资料完整度来自 `biz_enterprise_profile_stat`，申报指标来自 `biz_client_declaration`，断链使用 IP-RD-PS-成果转化关系实时计算。
- 已将企业服务中心调整为一级目录，新增“企业材料台账”作为默认跨企业资料视图。台账统一聚合财税、人员、IP、RD、PS、成果转化、合同、发票、制度文件、证书和账号，支持公司、资料类型与关键字筛选；仅在查看或编辑某条记录时进入对应企业详情。
- 客户端保留企业经办人自助流程，只收口与后台重复的展示和查询能力，不规划整体退役。

### P4 验证记录

- 已执行 `backend/sql/enterprise-workspace-menu-p1.sql`，12 条语句在本地数据库事务中成功完成。
- 已通过 `npm run verify:enterprise-workspace-menu-db` 回查 12 个动态企业服务中心菜单，均归属 `admin` 门户并要求 `Enterprise:Profile:List` 权限。

## 8. P0 首期范围

首期只做以下内容，避免在企业上下文未稳定前迁移大量表单：

1. 后台新增“企业服务中心”一级菜单和企业列表入口。
2. 企业详情页增加概览、资料完整度、待办、进行中申报和最近操作五个区块。
3. URL 统一为 `/enterprise/:enterpriseId/...`，所有详情请求显式携带企业 ID。
4. 新增企业范围校验与操作日志目标字段。
5. 复用现有企业、资料统计和申报数据，不复制客户端页面或接口。

暂不纳入：客户端视觉重做、客户端菜单迁移、全部资料表单重写、开放管理员模拟企业登录、批量导出和正式申报书文件生成。

## 9. 验收标准

| 验收项 | 标准 |
| --- | --- |
| 企业上下文 | 任一企业档案或申报页均能从 URL 确定企业，且切换不会污染其他标签页 |
| 权限 | 无企业范围权限的账号访问目标企业返回拒绝，不泄露摘要数据 |
| 资料边界 | 企业资料在档案域维护，申报详情只引用和诊断 |
| 审计 | 资料、材料、申报和审核写操作都能定位操作者与目标企业 |
| 页面体验 | 企业信息、风险、待办和下一步操作在首屏可见，复杂表单不嵌套在工作台中 |
| 迁移安全 | 现有 `web-client` 与 `/client/*` 持续服务企业经办人；后台重构不改变客户端权限边界 |
