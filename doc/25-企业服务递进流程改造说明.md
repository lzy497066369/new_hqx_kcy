# 企业服务递进流程改造说明

交付日期：2026-09-30。范围：本地源码与开发环境；未推送仓库、未部署远端。

## 1. 改造目标与边界

将用户的主要操作从“到平行模块中寻找功能”，调整为“先看当前待办，再进入相应阶段，办理后返回服务进度”。

主链路：**企业建档 → 企业资料补齐 → 政策匹配 → 创建申报 → 材料准备 → 审核补正 → 申报结果归档**。

- 企业档案、资料长期复用；每条申报独立显示办理进度，而不是把整个企业永久锁在一个阶段。
- 默认优先展示退回补正，其次草稿/材料准备，再到审核中与历史申报；同类申报按截止时间优先，之后参考更新时间。
- 用户可切换当前申报，也可以浏览任意阶段。企业资料不完整，不阻止政策浏览。
- 不删除旧业务模块，不新增业务表字段，不自动提交申报、审核或生成 AI 材料。
- 流程界面是现有数据的组织和导航层，不代替后端资格、企业隔离与权限校验。

## 2. 用户可见变化

### 2.1 统一服务进度入口

首页/企业工作台新增七阶段服务进度区：

1. 资料完整度与当前申报选择。
2. 七个阶段，显示已完成、需处理、待核验等状态。
3. 当前待办与推荐操作按钮，显示项目、截止日期、退回原因。
4. 点击阶段查看该阶段说明和缺项；资料缺项可进入相应资料模块，申报材料/资格问题进入本条申报详情核对。
5. 加载失败、材料核验失败分别提示并提供重试，避免错误地显示“已齐备”。

原并排入口收纳为“常用功能”或“其他功能入口”；通知、同步状态、公司切换和数据分析入口保留。

### 2.2 办理页面连接流程

企业资料、政策/项目、申报详情等主要页面增加“当前环节 / 返回服务进度”。从申报详情返回时携带申报 ID，使首页继续定位该申报。

企业切换、申报切换时清空旧数据；请求序列和企业上下文校验防止迟到响应覆盖新企业内容。页面激活时重新刷新进度。

### 2.3 状态措辞

| 业务信息 | 页面表达 | 不作出的推断 |
| --- | --- | --- |
| 资料统计清单为空 | 统计待确认 / 待核验 | 不视为资料完成 |
| 材料清单为空、核验失败 | 需确认清单 / 重试核验 | 不视为材料齐备 |
| 候选项目 | 待确认的匹配候选 | 不视为满足申报资格 |
| approved | 内部审核通过 | 不等于政府审批通过 |
| completed | 服务已完成 | 不等于已经正式归档 |
| cancelled | 已取消，保留办理记录 | 不标记审核成功 |

**归档边界：**系统当前没有独立“归档确认”实体。本次末阶段连接已有申报记录、结果留存和导出能力，不新增正式归档确认流程，不虚构归档完成。

## 3. 使用入口

### 客户端

- 服务地址：`http://localhost:5998/`。
- 登录后正式默认首页：`http://localhost:5998/dashboard/workspace`。
- 历史 `/home`、`/client/home` 菜单路径统一为 `/dashboard/workspace`，local 和 IAM 菜单采用同一规范化。
- 默认工作台与 ClientHome 复用同一页面，避免只改备用首页、真实首页仍是旧界面。
- 选择企业 → 查看建议下一步 → 进入对应业务页 → 保存/办理 → 返回服务进度。
- 多项申报通过“当前申报”下拉切换，退回记录优先处理。

**本地限制：**当前本地数据库未配置客户端 portal 的必要菜单；本地开发使用 local 认证。前端不会通过静态兜底绕过权限创建不可访问路由。需在既有账号/应用的合法菜单配置中补齐客户端菜单后，才可进行登录后的真实业务全链路验收。未自动注册应用、账号或角色，未修改远端 IAM。

### 管理端

- 服务地址：`http://localhost:5999/`。
- 登录 → 企业管理 → 企业资料/企业列表 → 行操作“服务进度”。
- 进入指定企业的工作台，按当前申报继续资料维护、材料核对、审核与补正。
- 本地菜单已补齐本次必要入口。已有登录会话需重新登录以刷新动态菜单和路由。

### 后端

- `http://localhost:3000/health` 为健康检查。
- 3000 是 API 端口，不是用户网页入口；根路径 404 不代表前后端服务故障。
