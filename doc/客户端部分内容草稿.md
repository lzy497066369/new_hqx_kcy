# 客户端部分内容草稿

## 1. 客户端定位

客户端是面向企业用户的业务操作入口，主要负责资料维护、申报提交、进度查看和内容浏览。它不是单纯的信息展示页，而是连接企业数据、申报流程和内容触达的前台操作系统。

## 2. 核心职责

- 维护企业基础资料，沉淀统一的企业主数据
- 提交申报事项，按规则补齐材料并跟踪状态
- 查看政策、公告、文章、视频和培训内容
- 接收后台审核结果，并根据反馈继续补件或重新提交
- 为后续 AI 辅助、内容触达和业务运营留出入口

## 3. 主要业务模块

### 3.1 企业资料

企业资料模块用于维护企业主体信息及扩展信息，包括：

- 企业基本信息
- 联系人信息
- 财务信息
- 员工信息
- 证照信息
- 合同信息
- 图片资料
- 知识产权资料

这一部分的目标是把分散在各处的信息统一沉淀，形成可复用的企业数据底座。

### 3.2 申报项目

申报模块用于展示可申报项目、填写申报内容、上传材料并提交审核。企业用户可以在这里查看申报要求、补齐缺失项、保存草稿和正式提交。

### 3.3 政策中心

政策中心用于浏览与企业相关的政策、通知和申报说明。它既是内容展示入口，也是企业回到资料维护和申报页面的触发点。

### 3.4 内容中心

内容中心用于承载文章、视频、培训等信息展示内容，帮助企业及时了解最新政策、业务要求和操作说明。

### 3.5 企业用户管理

企业负责人和企业用户可在客户端完成登录、绑定企业、切换企业和基础账号维护，保证不同角色能看到对应的业务数据与操作入口。

### 3.6 政策问答

政策问答用于承接企业对政策、申报条件和材料要求的常见咨询，降低人工重复答复成本，并提升企业获取信息的效率。

## 4. 典型业务流程

1. 企业用户登录客户端并绑定企业
2. 系统读取当前企业主数据和待办事项
3. 用户补充企业资料或进入申报项目
4. 按要求上传材料并提交审核
5. 后台返回审核结果，客户端展示通过、退回或补件状态
6. 用户根据反馈继续完善资料，形成闭环

## 5. 与后台和后端的关系

- 客户端负责查看、补齐、提交和追踪
- 后台负责配置规则、审核资料和管理流程
- 后端负责统一鉴权、数据存储、文件处理和接口服务

三者协同后，客户端就不仅是展示页面，而是企业业务流转的前端执行端。

## 6. 一句话概括

客户端部分主要承担“企业资料维护、申报事项提交、政策内容浏览、审核结果跟踪”四类核心动作，是企业用户完成业务闭环的主要入口。
