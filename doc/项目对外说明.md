# 项目对外说明

## 1. 项目概览

这是一套面向企业服务的业务系统，围绕企业信息管理、申报流程、资料补齐、审核流转、AI 辅助和内容发布展开，整体分为三部分：

- `vue-admin/apps/web-client`：客户端操作系统，业务上简称 `vue-client`
- `vue-admin/apps/web-admin`：后台管理系统，业务上简称 `vue-admin`
- `backend`：统一后端服务

这个项目最核心的业务模式可以概括成一句话：

- 客户端负责“补资料、提申报、看结果”
- 后台负责“配规则、看进度、做审核”
- 后端负责“统一鉴权、数据流转、文件和任务处理”

## 2. 系统分工

### 2.1 客户端 `vue-client`

客户端面向企业用户，主要做这些事：

- 登录、绑定企业、切换企业
- 维护企业基础资料、财务、员工、证照、合同、图片、知识产权等信息
- 提交申报、补充材料、跟踪状态
- 浏览政策、公告、文章、视频、培训内容

对应仓库目录：`vue-admin/apps/web-client`

### 2.2 后台 `vue-admin`

后台面向服务商和内部老师，主要做这些事：

- 创建企业、分配业务员、维护企业主数据
- 配置申报规则、材料项、分类和流程
- 审核企业资料、申报材料和流转状态
- 查看工作台、统计报表和 AI 辅助结果

对应仓库目录：`vue-admin/apps/web-admin`

### 2.3 后端 `backend`

后端负责统一承接前后端请求，主要能力包括：

- 登录和鉴权
- 企业、申报、内容、AI、统计相关接口
- 文件上传、导出、消息、队列任务
- v1 / v2 两套接口兼容

## 3. 业务角色

- 企业用户：在客户端维护资料、提交申报、查看进度
- 服务商/老师：在后台配置规则、审核资料、跟进企业
- 管理员：维护系统参数、账号、权限、菜单、基础字典

## 4. 客户端业务流程

### 4.1 登录与企业切换

客户端登录入口主要在 `vue-admin/apps/web-client/src/api/sys/user.ts`，核心接口是：

- `/v2/users/login`
- `/v2/users/info`
- `/v2/users/switch_company`
- `/v2/users/register`

流程是：

1. 用户登录
2. 后端返回用户信息和企业关联
3. 客户端读取当前默认企业
4. 必要时切换企业并刷新上下文

这一步决定了后续所有页面看到的是哪家企业的数据。

### 4.2 企业基础资料维护

客户端企业资料页主要在 `vue-admin/apps/web-client/src/views/enterprise/*`，对应接口主要在 `vue-admin/apps/web-client/src/api/enterprise/*` 和 `vue-admin/apps/web-client/src/api/system/*`。

常见接口包括：

- `/v1/company/info`
- `/v1/company/add_info`
- `/v1/company/create`
- `/v1/company/edit`
- `/v2/Enterprise/select`
- `/v2/Enterprise/edit`
- `/v2/Enterprise/create`
- `/v2/Enterprise/editShareholderSimple`
- `/v2/Enterprise/del`

资料维护内容通常包括：

- 企业主体信息
- 联系人信息
- 经营情况
- 股东信息
- 财务资料
- 员工资料
- 合同资料
- 证照资料
- 图片资料
- 知识产权资料

### 4.3 申报与资料提交

客户端申报相关页面主要在：

- `vue-admin/apps/web-client/src/views/declare/*`
- `vue-admin/apps/web-client/src/views/information/declare/*`

相关接口主要在：

- `vue-admin/apps/web-client/src/api/declare/*`
- `vue-admin/apps/web-client/src/api/information/declare/*`

常见接口包括：

- `/v1/declares/lists`
- `/v1/declares/create`
- `/v1/declares/edit`
- `/v1/declares/info`
- `/v1/declare_conf/getSelect`
- `/v1/declare_information/create`
- `/v1/declare_information/del`
- `/v2/company_declare_item/create`
- `/v2/company_declare_item/index`
- `/v2/company_declare_item/info`

业务顺序通常是：

1. 查看可申报项目或材料包
2. 进入材料清单或项目申报页
3. 逐项补齐信息并上传文件
4. 保存草稿或正式提交
5. 后台审核后继续补件或进入下一状态

仓库里能看出客户端同时存在两套申报表达：

- `v1`：偏资料包、材料清单、历史兼容
- `v2`：偏项目化、流程化、台账化

### 4.4 内容查看与政策浏览

客户端还承担内容展示，入口主要在：

- `vue-admin/apps/web-client/src/views/information/*`
- `vue-admin/apps/web-client/src/views/video/*`
- `vue-admin/apps/web-client/src/views/article/*`

相关接口主要在：

- `vue-admin/apps/web-client/src/api/information/*`
- `vue-admin/apps/web-client/src/api/information/article/*`
- `vue-admin/apps/web-client/src/api/information/video/*`

用户通常会：

1. 浏览政策、公告、文章、视频、培训资料
2. 查看申报说明和材料模板
3. 根据新要求回到企业资料页或申报页补件

## 5. 后台业务流程

### 5.1 企业创建与分配

后台企业管理主要在 `vue-admin/apps/web-admin/src/views/system/firm/*`，对应接口在 `vue-admin/apps/web-admin/src/api/system/firm/*`。

常见接口包括：

- `/company/lists`
- `/company/info`
- `/company/create`
- `/company/edit`

如果后续补充历史后端映射，可单独记录旧系统控制器路径；当前仓库内正式后端以 `backend` 目录为准。

这条链路的作用是：

1. 创建企业档案
2. 绑定业务员或老师
3. 建立后台和客户端之间的企业关联
4. 为申报和资料维护提供主数据

### 5.2 申报配置与规则维护

后台申报配置页面主要在：

- `vue-admin/apps/web-admin/src/views/system/declare/*`

对应接口主要在：

- `vue-admin/apps/web-admin/src/api/system/declare/index.ts`
- `vue-admin/apps/web-admin/src/api/system/declare/task.ts`
- `vue-admin/apps/web-admin/src/api/system/declare/item.ts`

常见接口包括：

- `/declare_conf/lists`
- `/declare_conf/create`
- `/declare_conf/edit`
- `/declare_conf_class/lists`
- `/declare_conf_class/create`
- `/declare_conf_item/lists`
- `/declare_conf_item/create`

对应正式后端能力后续应逐步沉淀到 `backend/src/modules/*` 下的业务模块中。

后台一般按这个顺序工作：

1. 定义申报项目
2. 定义分类和区域
3. 定义材料项、字段和校验
4. 客户端按规则生成页面

### 5.3 申报审核与资料处理

后台申报审核和资料查看主要在：

- `vue-admin/apps/web-admin/src/views/information/declare/*`

对应接口主要在：

- `vue-admin/apps/web-admin/src/api/information/declare/*`

常见接口包括：

- `/c_declare/lists`
- `/c_declare/create`
- `/c_declare/file_lists`
- `/c_declare/save_file`

核心动作是：

1. 查看客户端提交的申报和材料
2. 核对缺失项、附件和状态
3. 必要时要求客户端补充资料
4. 将结果同步到后续流程或统计页面

### 5.4 工作台、统计与 AI 辅助

后台工作台和 AI 页面主要在：

- `vue-admin/apps/web-admin/src/views/dashboard/*`
- `vue-admin/apps/web-admin/src/views/ai/*`
- `vue-admin/apps/web-admin/src/views/statistics/*`

对应接口主要在：

- `vue-admin/apps/web-admin/src/api/dashboard/*`
- `vue-admin/apps/web-admin/src/api/ai/*`

后台这里不只是展示数据，更偏向运营判断：

- 哪些企业资料缺失
- 哪些申报流程卡住
- 哪些任务需要回客户端补资料
- 哪些场景可以用 AI 辅助审核或分析

## 6. 典型业务闭环

### 6.1 企业资料补齐

1. 后台创建或导入企业
2. 客户端登录并绑定企业
3. 客户端补基础信息、财务、员工、证书、图片、合同等
4. 后台在工作台查看补齐进度
5. 后台按缺失项继续催办或审核

### 6.2 申报项目流转

1. 后台配置申报项目、分类和材料项
2. 客户端看到可申报项目
3. 客户端按要求填写并提交
4. 后台审核、退回、补件或通过
5. 结果回写到申报状态和统计页面

### 6.3 内容驱动补资料

1. 客户端查看政策、公告或培训内容
2. 发现新要求后回到企业资料页
3. 补充材料或重新提交申报
4. 后台根据新状态继续流转

### 6.4 AI 辅助审核

1. 后台或客户端触发 AI 审核、AI 规则或 AI 财务辅助
2. 生成任务、文件或分析结果
3. 结果回到工作台或申报页
4. 人工做最终确认

## 7. 数据与状态流转

### 7.1 客户端到后端

- 页面表单和文件上传先进入前端 API 层
- 前端通过相对路径请求后端
- 本地开发时走 Vite 代理
- 生产环境直接走发布后的后端地址
- 后端返回统一格式后，前端再做列表、详情、弹窗和状态展示

### 7.2 后台到客户端

- 后台负责配置和审核
- 后台定义的申报规则影响客户端表单
- 后台处理结果影响客户端看到的状态、待办和缺失项

### 7.3 关键数据关系

- `users`：客户端用户
- `admin`：后台管理员
- `company`：企业主数据
- `users_company`：用户和企业的关联
- `declare_*`：申报配置和申报数据
- `company_*`：企业各类扩展资料

## 8. 接口和控制器的对应习惯

### 客户端

- `v1` 接口更多是资料型、历史兼容型
- `v2` 接口更多是项目型、流程型、AI 型

### 后台

- 当前正式后端以 `backend/src/modules/*` 为准。
- 如果需要对照历史系统，再单独补充旧控制器和旧接口映射。

### 代理和联调

后台管理系统和客户端操作系统本地开发均通过 `/api` 代理联调后端，代理会移除 `/api` 前缀并转发到 `http://localhost:3000`。生产环境直接使用各应用的 `VITE_GLOB_API_URL`。

- `vue-client`：`/api` -> `http://localhost:3000`
- `vue-admin`：`/api` -> `http://localhost:3000`

联调时的判断原则是：

- 请求是相对路径且命中代理前缀，才会走本地代理
- 如果前端已经写成完整后端域名，代理不会生效
- 前缀不匹配时，请求会直接落到当前前端地址

## 9. 推荐给外部项目的阅读顺序

如果要把这套项目给别的项目看，建议先按下面顺序理解：

1. 看系统分工，先分清客户端、后台和后端
2. 看客户端业务流程，理解“补资料、提申报、看结果”
3. 看后台业务流程，理解“配规则、看进度、做审核”
4. 看数据与状态流转，理解前后端怎么串起来
5. 看接口和控制器对应习惯，方便后续联调定位

## 10. 一句话总结

这套系统可以稳定地按三条主线理解：

- 客户端负责查看、补齐、提交、追踪
- 后台负责配置、审核、统计、催办
- 后端负责统一鉴权、数据流转、文件和任务处理

只要把某个页面放进这三条线里，基本就能判断它该调哪组接口、落到哪类后端控制器、对应哪类业务表。
