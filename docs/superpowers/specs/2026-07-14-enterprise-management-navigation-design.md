# 企业管理一级目录重构设计

## 目标

将后台企业相关能力按使用目的拆为三个并列一级目录，避免把统计、材料台账和申报处理混在同一个“企业服务中心”目录下。企业经办人继续使用客户端；后台仅面向具备 `Enterprise:Profile:List` 权限且处于授权企业范围内的管理员和项目老师。

## 信息架构

| 一级目录 | 默认页 | 二级页与职责 |
| --- | --- | --- |
| 企业服务中心统计 | 企业列表 | 企业列表以卡片呈现企业基础信息、资料状态、行业、地区和快捷操作；保留导入、查看、编辑、企业用户、进入企业工作台、删除能力。 |
| 企业材料台账 | 材料台账 | 顶部企业选择器默认选中当前用户可见列表的第一个企业；财税、人员、知识产权、RD、PS、成果转化、合同、发票、制度文件、证书、账号在同一台账中按类型聚合展示。用户可切换至其他可见企业，或清空选择器查看全部企业。 |
| 企业申报管理 | 申报列表 | 显示当前用户有权查看的全部企业申报，可按企业、状态、关键字筛选；记录显示企业名称。点击记录进入独立详情页，路由显式携带 `enterpriseId` 和 `declarationId`。 |

显式 `enterpriseId` 的企业工作台、资料域维护页、证据链和旧的按企业申报页保留为隐藏详情/维护路由，不作为一级目录或可见菜单入口。

## 路由与菜单

静态路由和 `sys_menu` 使用相同的三个根路径：

- `/enterprise-service-statistics`：重定向至 `/enterprise-service-statistics/enterprises`。
- `/enterprise-material-ledger`：直接进入材料台账。
- `/enterprise-declaration-management`：重定向至 `/enterprise-declaration-management/declarations`。

数据库菜单通过新的可重复执行 SQL 补丁迁移，不能修改已经执行过的 P1 菜单脚本。企业列表是“企业服务中心统计”的二级菜单；材料台账和申报列表各自是独立一级菜单的默认页面。旧动态维护路由仍挂在隐藏菜单节点上，确保刷新、权限菜单解析和已有深链接可用。

## 页面边界与组件

### 企业列表

路由页只负责编排数据与弹窗。卡片列表拆分为：

- `EnterpriseCardFilters`：企业名称、信用代码、行业、资料状态和启用状态筛选，向父级发出筛选变更事件。
- `EnterpriseCardList`：负责网格、加载态、空态和分页，向父级发出页码与卡片动作事件。
- `EnterpriseCardItem`：只渲染一个企业卡片及其快捷操作。

卡片仍通过现有 `getEnterpriseProfilesApi` 拉取分页数据。详情、编辑、企业用户、导入和删除继续使用现有抽屉/弹窗与权限接口，避免重复实现业务能力。

### 企业材料台账

路由页加载当前用户可见的企业列表。企业列表成功返回后，若没有已选企业，则将首个企业 ID 设为默认值，再发起台账请求，避免首次进入混合展示全部企业。企业选择器允许切换到其他企业，允许清空为“全部企业”。

台账使用现有 `GET /enterprise-workspace/materials`，传递 `enterpriseId`、`type`、`keyword`、分页参数。资料按类型分组展示，类型筛选和关键字筛选作用于当前选定企业或全部企业；点击记录进入对应企业工作台，保持跨企业汇总页与单企业维护页职责分离。

### 企业申报管理

新增 `GET /enterprise-workspace/declarations` 跨企业列表接口。它复用 `EnterpriseProfileService.list(..., currentUser)` 取得用户可访问的企业范围，再查询这些企业的申报；不得信任前端传入的企业 ID 作为权限依据。响应包含 `enterpriseId`、`enterpriseName`、项目名、状态、当前节点、待补材料数、截止时间和更新时间。

申报列表页只处理列表、筛选、分页和跳转。申报详情页从路由读取 `enterpriseId`、`declarationId`，复用现有详情接口 `GET /enterprise-workspace/enterprises/:enterpriseId/declarations/:declarationId`。详情接口本身继续执行企业范围校验；因此直接篡改 URL 不会泄露其他企业数据。

## 数据流与权限

前端状态以路由参数和局部筛选状态为单一来源：子组件通过 typed props 接收数据，通过 emits 将筛选、分页和动作上报，路由页保留请求和导航职责。不可在子组件中直接修改父级数据。

管理员可查看其权限范围内的全部企业；项目老师仅可查看已绑定企业；企业经办人不获得后台菜单及接口访问能力。三个聚合接口均由后端重新计算可见企业范围，前端筛选仅用于缩小已授权范围。

## 错误处理与验收

- 企业列表、材料台账和申报列表请求失败时保留当前有效数据并展示统一错误反馈；加载态和空态必须明确。
- 无可见企业时，材料台账不请求带空企业 ID 的默认单企业数据，显示空态；“全部企业”只在用户显式清空选择器后使用。
- SQL 菜单补丁可重复执行，静态菜单校验和数据库回查同时验证三个根菜单、企业列表子菜单及隐藏维护路由归属。
- 项目老师使用接口和直接 URL 都只能看到绑定企业；跨企业申报详情仍经过 `enterpriseId` 范围校验。
- 前端通过 lint、typecheck、build 验证；后端通过现有安全边界及菜单校验脚本验证。

## 非目标

- 不迁移企业经办人的客户端工作流，也不向其开放后台企业服务中心。
- 不重写现有企业资料维护表单、导入流程或按企业申报工作台。
- 不在本轮实现正式申报书生成、批量导出或新的审核流程。
